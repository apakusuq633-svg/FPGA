本文对照以下两份文稿，列出仍缺少当前匹配版本实板数据的项目，并说明应如何测量、保存哪些记录、回填到哪里：

- [第一部分：作品概述](../../../../第一部分_作品概述_重写稿_2026-10-28.md)，重点为1.4性能指标、1.5创新点、1.6设计流程及1.7实板验证计划。
- [第二部分：系统组成及功能说明](../../../../第二部分_系统组成及功能说明_2026-11-01.md)，重点为2.2硬件和2.3软件中各模块的实际运行效果。

## 1. 核查结论

**当前最缺的是目标板上的真实性能、实际阵列标定和真实声场应用数据。第一部分已有的大多数性能数字来自RTL周期换算或Windows宿主计时，不能直接改写为当前九麦系统的实板指标。**

项目并非从未上过板。仓库保留了PDM ILA、旧PS回放、九麦历史缓存与分离诊断管线的板测记录；这些记录有各自的版本和输入边界。它们不能覆盖后续源码、内存属性、前端、模型和负载发生变化后的全部结论。

本文列出 **24项待补或待复测的实板数据B01—B24**。此外，单列匹配发布包、实现资源／静态时序、机械图纸和照片等配套材料，避免把这些材料都误称为“需要上板测量的数据”。

本文仅审阅当前文件与已有记录，没有重新连接板卡、下载程序或执行板测。“未取得当前证据”表示本工作区不足以支持该项当前版本结论，不等于断言用户在其他位置从未测过。

## 2. 上板前先解决的前提

### 2.1 P0：冻结并恢复匹配发布物

本次检查发现，`profiles/full_gui9/program_latest.ps1`指向的`build/gui_offline_ready_20261027/program.ps1`不存在；`build/circular9_direction_release`、`build/circular9_optimized_hw`、`build/circular9`及`build/c9opt`也不在当前工程目录中。旧日期文档中的“包已生成”不能证明当前工作区已有可直接下载的匹配包。

先恢复原有完整归档，或从冻结源码重新生成bit、XSA、BSP、PS ELF、RV32镜像及方向LUT，核对实际加载物。每轮测试保留源码提交号、编译参数、发布清单、各文件SHA-256、下载日志和实际运行版本。三架构对照另需分别冻结对应构建与计时入口。

这是板测身份和复现前提，**不是新增性能数值**；没有完成这一步，之后采到的时间和录音无法可靠归属当前文稿版本。

### 2.2 当前仍未解除的配置保护

当前[生成镜像头文件](../sw/acoustic_circular9_image.h)保留：

```c
ACOUSTIC_GEOMETRY_CONFIRMED = 0
ACOUSTIC_CALIBRATION_VERSION = 0
ACOUSTIC_CALIBRATION_STATUS = "unmeasured"
```

[九麦配置](../configs/circular9_array.json)中的`board_tested=false`、斜向坐标未独立量测，以及[轴承配置](../configs/bearing_6004_2zr.json)中的`baseline_available=false`、`model_compatible=false`，也表明当前配置尚不提供完整实物验收依据。

这些标记不是靠手动改成“通过”来补数据。应先取得B01—B04及B18—B20所需证据，再按既有校验和生成流程接入。未满足条件时，诊断未知、可信故障方向为空或GSC旁路可能是正确的保护行为。

旧文档中的30 mm理想声孔圆、“全部共享区非缓存”等说明属于历史状态。本次采用当前非均匀声孔坐标，以及CPU历史／任务段Normal WB共享、DMA槽显式维护缓存的实现；不要按旧记录选错测试对象。

统一输入驻留位置、传输方向、结果数量、质量后处理和轮询／校验范围。阶段表只比较相同边界，端到端表包含对应实际传输和控制。跨A9与PL比较实际时间，分别记录硬件计数器频率，不能直接相除两种不同频率的周期数。

生产九麦固件的声学指令发射并非由一个通用`FW_ACCEL=0`开关自动切换为等价标量路径；旧4麦对／256格测试也不能拿来替代36麦对／1024格基线。可复用[已有九麦标量参考与结果][scalar]，但仍需完成A9入口、访存／传输及板上计时适配。

PL标量若达不到连续Hop预算，可在冻结快照上完成单任务性能对照，同时明确其不满足连续实时服务；不要把无界积压的测试当作公平稳态吞吐。B06的独立开关也需有真实等价实现，无法分离某项收益时只报告组合架构收益。

### 4.2 延时的四个终点分开填写

| 边界 | 含义 | 注意事项 |
|---|---|---|
| 首个对齐PCM→RV32稳定发布 | PL数字定位链，包含该窗采样收集 | 若沿用项目小于10 ms的数字链目标，只按该边界检查；还需保存超限次数 |
| 首个对齐PCM→CPU0首次取得有效图 | 加入结果发布、读取和服务调度 | 不可用上一行的9.17 ms仿真数值替代 |
| 声学事件／可追溯输入标记→页面可见 | 包含采集前端、网络及浏览器的观察链 | 记录播放／触发装置延迟，跨时钟需校准或共用可识别标记 |
| 故障发生→首次可信诊断／拾音生效 | 含真实观察、方向支持、分离、模型与控制 | 1.024 s观察窗仍存在，毫秒级定位不等于毫秒级故障确认 |

PL、PS、PC的原始时间戳不能直接相减。优先保存同一采样区间的序号与阶段标记，再建立可验证的时钟对应关系。PDM上电50 ms等待、滤波群延迟、稳态处理延时分别测量和报告。

### 4.3 持续运行的计数与有效率

第一部分要求至少1000个有效稳态窗口，执行时必须写清窗口对象：

- 1000个PL定位窗按512点步长只覆盖约3.28 s，不能作为长期稳定性证明。
- 1000个有效诊断窗即使恰按512 ms步长持续产出，也需约512 s；实际有跳步、拒绝或耗时不足时更长。
- 建议另做至少1 h连续负载观察，再根据实际使用场景延长；这是本清单建议，不是已完成记录或官方规定时长。
- 总输入、全部窗口、有效输出、拒绝、超期、丢样和恢复全部统计。采样有效率与诊断有效率分别计算；不得只对成功输出计算结果而隐去未输出比例。
- 512 ms为诊断发起步长；辅助搜索200 ms新鲜度、方向覆盖90%、排队输入512 ms以及3 s总耗时／结果年龄限制是条件，不保证能持续2 Hz有效诊断。
- P99和观测最大值只描述本次条件下的样本分布，不写成已证明的严格最坏执行时间。

## 5. 声学与故障数据的采集要求

### 5.1 每段录音至少携带这些真值

| 数据类别 | 最小记录字段 |
|---|---|
| 采样身份 | 九路s16le交错、156250 Hz、首／末样本号、帧数、session、epoch及PCM哈希 |
| 声场 | 实际声源个数、各源方位／俯仰／距离、阵列安装朝向、房间和背景噪声、布置照片 |
| 工况 | 设备与轴承型号、参考转速、PPR或手动转速依据、故障状态及标签来源 |
| 处理身份 | bit／ELF／RV32／LUT／几何／标定／C9F2／C9S3／模型版本及实际频点掩码 |
| 同窗输出 | 候选及轨迹、搜索支持、分离音频、质量报告、18维特征、诊断原因与控制事务 |

1024×9短快照只有6.5536 ms，不能通过不连续拼接冒充1.024 s诊断观察。长窗取证可使用[连续PCM导出与离线回放说明](issues/137-offline-closure-and-board-readiness.md)所述工具，保存160256原始帧、元数据及哈希；导出对负载的影响仍属于B24待测内容。

### 5.2 单源、多源和故障模型分别评价

单源定位优先报告球面角误差，可按`acos(clamp(u_est · u_true, −1, 1))`计算；粗格与细角用同一批输入比较。方向网格和拟合小数位不是测角精度。测试中可记录用尺量出的声源距离作为场景条件，系统本身仍不输出距离。

多源先用大间隔验证完整链路，例如已有计划的两源±50°，再逐步减小夹角和改变强弱差；25°是当前分离接受门槛，不是已证明的可分辨角度。6／12 dB应注明在阵列处的测量定义，不能仅按播放器音量百分比推定。

分离效果同时看抑制与保真。源贡献对照应从同一混合快照学得权值后冻结，不对各单源重新拟合再计算同一分离器的SIR。真实房间中若缺乏可信的分量参考，应报告能够测得的音频、频带保留、泄漏代理、诊断变化及适用限制。

模型数据应来自当前空气声采集和生产前端。扬声器播放真实故障录音可以验证回放声场中的处理链，但须与真实设备运行分开统计。训练和验证按原始录制ID隔离，不能把同一录音的重叠窗分到两侧；测试集不用于调门槛。

正常／故障／干扰三类结果、正常基线异常检测，以及FSTF六类实验结果分别报告。六类实验尚未验证，当前文稿未承诺正式六类分类能力；不用为了补本清单而强行把实验标签用于可信方向控制。正常基线异常也不能直接改写为已确定轴承故障。
