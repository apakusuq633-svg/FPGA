# 011 BRAM 读是两拍延迟

**症状** 新写的 ANC 序列发生器收 ROM 数据时**总是拿到上一个地址的值**。
表里每个值都是合法的正弦采样，所以错得不显眼 —— 输出是个"频率不对的正弦"，
不是垃圾。

**误判** 第一版草稿里我把收数写在发地址的**下一拍**（t+1），当时觉得"同步读一拍出数"。

**根因** BRAM 同步读的时序是：

```
t   : rom_addr_q <= new_addr      （发地址）
t+1 : rom_addr_q 已经是新值，但 rom_q 仍是旧数据
t+2 : rom_q <= sintab[new_addr]   ← 数据在这里才稳
```

所以**收数必须在 t+2**。

**修法** 收数窗口从 `step_q >= 1 && < 13` 改成 `>= 2 && < 14`，
序列总长相应加两拍（`S_BQ` 14）。

**复现/指纹** 输出量级正常、形态正常，但**相位/频率系统性偏移**。
任何"同步读存储"的地方都要数一遍：发地址 → 数据回来，中间隔几拍。
本仓库的 `rv32_dtcm` 是"隔拍应答"，`rv32_itcm` 是同步读，各不一样，别套用。
