# 005 陷波一直是关的

**症状** `--check` 的 Test E（混合）打不过 Test D（纯宽带），而且**改 ρ 完全不影响结果**
（0.99 / 0.995 / 0.9975 三个值测出来逐位相同）—— 这个"太干净了"本身就是线索。

**误判** 归因于"陷波抑制不够、宽带支路去追音调"，并写进了 README §40.7。

**根因** `gen_anc_hybrid.py` 的 `configure()` **从来没设 `NotchBank.en`**，
而它的默认值是 `[False]*4`；系数计算里 `live = self.en[k]` 会把深度强制成 0。
**第一版的陷波一直是关的，§14「宽带用陷波后的参考」根本没被跑到过。**

> **026 追记**：陷波链已整个撤掉，`NotchBank` 不存在了（换成 `ProjectionBank`）。
> 这条坑照旧成立 —— `configure()` 里 `prj.live` / `prj.en` 同样默认关，
> 所以产物和 `tb_anc_hybrid` 也仍然是"音调支路关"的配置。

`tb_anc_hybrid.v` 是按这份黄金文件生成的，所以它忠实照做，也把 `NK_CFG` 的 en 位写成 0。

**修法** 在 `configure()` 里加 `anc.notch.en = [True] * K_SLOTS`。
但**要同时改三处**，只改一处会让 TB 变红：生成器、TB 的 `NK_CFG` 写入、
重生成 `sw/anc_expect.hex`。实测两种配置：

| | 陷波关 | 陷波开 |
|---|---|---|
| 只开窄带 | 7.56 | 7.56 |
| 只开宽带 | **20.86** | **3.07** |
| 混合 | 16.93 | 5.87 |

**复现/指纹** **改参数完全不影响输出** —— 遇到"参数扫了一圈数字一个都不动"，
先确认那个参数到底有没有接到数据通路上。这类"死位"是本仓库反复出现的模式
（`MODE.notch_en` / `NK_CFG[0]` 也曾经是死位）。
