# 078　TB 在同一个时间步里读组合译码 ⇒ 读到上一笔的值

**症状** 新 TB 灌 LUT/R 都成功（逐条比对 0 错），但**任何回读都不对**：
读 STATUS 拿到的是别的寄存器的数、读 P 全错、连"保留值必须报错"都失败。

**误判** 先怀疑 RTL：窗口自增写错了？读口没接？
（"写对了、读全错"看起来最像读通路坏了。）

**根因** TB 里写成一串同刻赋值：

```
@(negedge clk); core_rd = 1'b1; core_addr = a; d = core_rdata;
```

`core_addr` 与 `d = core_rdata` 在**同一个时间步**执行，而读译码是另一个
`always @(*)` 进程 —— 它还没重算，`core_rdata` 还是**上一笔地址**的值。
于是"读什么都是上一个寄存器的数"，而判据的形状像极了 RTL 坏了。

**修法** 采样前加 `#1`（本仓别的 TB 一直这么写，见 `tb_srp_scan` 里的
`@(posedge clk); #1;`）。窗口 TB 的 `core_read` / `ps_read` 都加了。

**复现/指纹** 「同一段代码，**写**的判据全过、**读**的判据全错」——
先问"是不是我在错的时刻采的样"，而不是"读通路坏了"。

⚠ 与 [044](044-tb-read-wrong-sample-phase.md) 同族：**判据与采样不在同一时刻**。
这类坑的共同形状是"FAIL 了，但打印出来的值看着是对的"。
