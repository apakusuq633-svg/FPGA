# 063 两套接线表并存：**备选方案**被写成了现状，差点让人接错排针

**日期**：2026-10-04
**状态**：**已修**（改的是文档，不是 RTL/xdc）
**相关**：[052](052-j4-pinout-extraction-traps.md)（J4 线序抽取）、
P-13 / `docs/board_io.md` §8

---

## 1. 症状：同一个问题，两份文档给出不同的排针

| 出处 | 说 PDM 接哪 |
|---|---|
| `constrs/ps_pl_wrapper.xdc`（**实现**） | **J3**：`pdm_clk_o`=J3.36/V16，`pdm_din_i[0..7]`=Y16…V17 |
| `docs/board_io.md` §8「8 通道引脚表（**现状**）」 | **J3**，与 xdc 逐位相同 ✓ |
| `docs/mic_array_spec.md` | **J3** ✓（"9 根脚，J3 上就够，不需要动 J4"） |
| `docs/pdm_array_spec.md` **速览表** | **J4** ✗ |
| `docs/pdm_array_spec.md` **P-13** | **J4** ✗（"8 通道走 J4 的 Bank34 那 11 根"） |
| `README.md` §0.2 | **J4** ✗（"8 通道 PDM 只用 J4 上那 11 根 Bank34"） |
| `docs/board_io.md` 上电量清单 | **J4** ✗（"8 通道 PDM 只用 J4 的 Bank34 那 11 根"） |

**关键差别是脚位**：J3 的 PDM 时钟是 **V16**（J3.36，紧邻 J3.37 的 GND），
J4 的备选方案是 **W15**（J4.36）。**照错的表接线，麦一个都不会响，而且不报任何错。**

## 2. 根因：一份"现状表"和一份"备选推荐"同时存在，引用时没区分

`board_io.md` §8 里**两套都在，而且是分开的两节**：

- 「### 8 通道引脚表（**现状**，全部 Bank 34）」← J3，实现口径 ✓
- 「### 8 通道 PDM 直接接 **J4** 的**推荐分配**」 ← J4，**备选** ✓

但 **P-13 写得很主动**（"电气可行"、"8 通道走 J4 的 Bank34 那 11 根"），
**速览表那一栏「接哪里」直接填了 J4 并引 P-13**，README 又引速览表 ——
**引用链一路传下去，把"备选"传成了"现状"。**

⚠ 这正是 CLAUDE.md §1 说的「**陈旧的口径比没有口径更危险**」：
它看起来像结论，而且**引用它的人无从察觉**。

## 3. 判定依据（不是偏好，是实测）

有三条互相独立的证据都指向 J3：

1. **xdc 是唯一被工具消费的**，它写 V16。用户也确认过「xdc 里的数据都是对的」。
2. `board_io.md` §8 那张表的**标题就写着「现状」**，列头是「**J3** 针」，
   而且 V16 与 xdc 逐位相同。
3. **物理理由**：xdc 注释与 §8 都写着 —— V16 是整条 2×8 排线上**唯一与 GND
   （J3.37）相邻**的信号位，而 PDM_CLK 要扇出到 8 个麦、是这条通路上频率最高的
   信号（2.5 MHz）。J4 的备选方案给的理由是"与 J4.37 相邻"，**同样成立但位置不同**。

## 4. 修法

- `pdm_array_spec.md` 速览表「接哪里」改成 **J3** 并列出**实际脚位**，
  注明 J4 只是备选、未进 xdc。
- `pdm_array_spec.md` **P-13 开头加状态注**：备选方案、尚未实施、不要照它接线。
- `README.md` §0.2 与 `board_io.md` 上电量清单里那两处"只用 J4"改成 J3。

## 5. 复现指纹

- **同一份文档里出现「现状 / 推荐 / 备选 / 将来」多种方案** ⇒ 引用那一栏之前
  **先落实现**（谁的脚位在 xdc 里 = 谁是真的），别顺着"看起来最完整"的那节抄。
- **接线类数据冲突时，判据永远是 xdc**（唯一被工具校验、且能直接下到板上的那个），
  其次是标着「现状」且脚位与 xdc 逐位一致的表。
- **本文的形态与 [059](059-pdm-capture-first-frame-fullscale.md) 是同一类**：
  两个来源都"看着合理"，其中一个已经过期。**独立证据只有在确实无关时才独立。**
