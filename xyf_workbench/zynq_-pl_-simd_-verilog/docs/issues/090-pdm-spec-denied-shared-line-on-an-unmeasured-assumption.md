# 090 P-04 / P-06 都建立在一个**没量过、而且对三态麦不成立**的假设上

**症状** 两条写在规格里的结论，回头看都是同一个假设的下游：

1. **P-06**（`pdm_array_spec.md`）把「每根数据线挂 2 个麦」判为**不做**，理由一句话：
   「它把每个通道的采样窗口砍掉一半，对追求 TDOA 精度不划算」。于是 16 麦的方案
   被推去要 **17 根信号脚**（16 根 DIN + 时钟），去吃 J3 的 5–14（原 LCD/触摸段）——
   而载板从来没按这个排过线。
2. **P-04** 判定「采错时钟沿不影响定位，所以这条不用等 datasheet」，
   推理是「采错沿只让整条流推迟**恰好一个位周期**，而且所有通道推迟相同，
   TDOA 取差时精确抵消」。

两条都成立的前提是同一个：**麦在整个位周期里都在驱动数据线**。

**误判** 拿到实物 datasheet（Infineon **IM73D122V01**）之前，这个前提被当成了
「PDM 麦的常见行为」。P-14 里其实已经写着 datasheet 还没到手、四条都按默认值兜，
但 P-04 的标题是【**已定**：不用等 datasheet】—— 结论被写成了已定的，
前提却没有一条实测撑着。

**根因** IM73D122V01 是**分时三态**的。datasheet §3.5 Table 8：

| 通道 | 驱动沿 | 高阻沿 | L/R 接法 |
|---|---|---|---|
| DATA1 | **下降沿** | 上升沿 | **GND** |
| DATA2 | **上升沿** | 下降沿 | **VDD** |

⇒ **单麦配置下数据线也只有半个周期有效**（另半个周期麦是高阻）。
两条结论因此各自反转：

- **P-06 的理由不成立**：窗口本来就只有半个周期，共线**一分余量都不损失**。
  16 麦共线 = 8 根 DIN + 1 根时钟 = **9 根**，正是 xdc 里已经约束、2026-10-04
  已经上板验过的那 9 根。
- **P-04 的推理不成立**：采到错的那半个周期，读到的**不是**一个移位的位，
  而是**另一个麦的位**（被线容保持）或者悬空电平 ⇒ `SAMPLE_TICK` 是**真时序约束**。

**修法**
- RTL：`rv32_pdm_clkgen` 出两个抽头（`HOLD_TICK` / `CONSUME_TICK`），
  `rv32_pdm_array_rx` 加 `MICS_PER_LINE`，低相位锁存保持到消费点，两个相位共用
  一套抽取节拍（零偏斜、下游 valid/frame/frozen 一行不改）。
- 数值：`pdm_decim.py` 新增 §8，用 datasheet 的 `t_DD/t_DV/t_HZ` 把 tick 扫出来；
  接进 `verify.ps1` 第 29 项。
- 规格：P-06 改写、P-04 按 datasheet 重写、`board_io.md` §8 与
  `mic_array_layout.md` L-06.6 同步。

**⚠ 连带发现的同一个病**：`tb_pdm_array_rx` 的麦模型 `pdm_mic_model` **整周期都在
推数据**，从来没高阻过 —— 所以旧的第 8 段「采样相位反证」一直是**因为模型不真而绿**。
这正是 [045](045-counterexample-not-connected.md) 那一类。修法是把激励改成
`tri0` + 分时三态，反证才第一次真的成立（现为 TB 第 8/9b/11 段）。

**复现指纹** 「规格里写着某个参数不用等 datasheet / 不影响结果」+「那个结论依赖
器件在某个时间窗内的行为」⇒ 去 datasheet 的时序表里找那个窗的真实长度。
本次两个数：窗口 = 半个位周期（不是整周期）；`t_DV` max = 100 ns。
**凡是"公共量所以抵消"的论证，先问一句那个量是不是真的公共。**
