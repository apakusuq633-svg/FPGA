# 073 — 阵列的 `ch[0]` **同时选延迟线和 w 系数 bank**（不只是延迟线）

**状态**：已修（2026-10-05）

---

## 症状

GSC 的三条交织流按"一条延迟线一条"分配：

| 流 | `data` | `ch` | 期望的线 |
|---|---|---|---|
| mix | 0 | 0 | `x` |
| tgt | 1 | 0 | `x'[0]` |
| oth | 1 | **1** | `x'[1]` |

在 `tb_gsc_vec_map` 上单测这条线：

```
x'[0] 线: result = 61440   闭式期望 61440     ✅
x'[1] 线: result = x       闭式期望 61440     ❌ 是 X
```

固件里对应的现象：`p_e_target` 与模型**逐位相等**，而 **`p_e_other` 是 X**
（`GSC +inf dB`）。**同一个自适应滤波器的三次求值，两次对、一次 X。**

## 根因

```verilog
// rv32_vec_unit.v:186
wire [CAW-1:0] c_waddr = (ch3_q[0] ? W1_BASE : W0_BASE) + {2'b0, p3_q};
```

**`ch[0]` 选的是 `w` 系数 bank**，而不只是延迟线；延迟线才是用整个 2 位 `ch` 选的
（`line_base = XP0_BASE + ch*64`）。

⇒ 对应关系是：

| `ch` | 延迟线 | `w` bank |
|---|---|---|
| 0 | `x'[0]` | **W0** |
| 1 | `x'[1]` | **W1** ← 从没被初始化过 |
| 2 | `x'[2]` | **W0** |
| 3 | `x'[3]` | **W1** |

`W1_BASE = 64`，而 TB 只 poke 了 word 0~14（W0 的区间）⇒ 读 `x'[1]` 时系数是 **X**，
`X × 数据 = X`。

**这不是 RTL 坏 —— 是设计的语义没读全。** 源码注释里写着
「选 w bank 时只用 ch[0]（输出通道 s）：MIMO 的两个输出滤波器各一条」，
但那条注释在 `ch_q` 的声明处，**不在 `c_waddr` 那行**。

## 修法

**让三条流都落在 W0**（GSC 的三次滤波必须共用同一套权值）：

| 流 | `data` | `ch` | 线 | funct7 |
|---|---|---|---|---|
| mix | 0 | 0 | `x` | `0x00` |
| tgt | 1 | 0 | `x'[0]` | `0x08` |
| **oth** | 1 | **2** | **`x'[2]`** | **`0x28`** |

**一行 RTL 都不用改** —— 只是选另一条线。

## 复现指纹

```bash
iverilog -g2005 -I rtl -s tb_gsc_vec_map -o build/tb_gsc_vec_map.vvp -c scripts/filelist.f
vvp build/tb_gsc_vec_map.vvp | grep "线"
#   → x'[0] 线: result = 61440        ✅
#   → x'[2] 线(ch=2, W0): result = 61440  ✅
#   改回 ch=1 会得到 x
```

## 教训

1. **一个 2 位字段可以同时喂两个译码器，而且两半用法不同。**
   `ch[1:0]` 全线选延迟线，`ch[0]` 单独选系数 bank。
   查端口表时要找**每一个用到这个字段的地方**，不是只看声明处的注释。
2. **"三次求值应当共用一套权值"是个隐含约束**，而硬件里"共用"意味着
   **同一个物理 bank**。选线时不能只看"哪条线空着"。
3. **X 是朋友**：它把"读了没初始化的存储"变成了一次立刻可见的失败。
   如果 W1 恰好残留了上一轮的旧值，这次会**静默地算出一个像模像样的错数**。
