# 088 关键路径其实在 `u_steer`：一次"看到资源数变了就下结论"的误判

**状态**：已修
**日期**：2026-10-08
**阶段**：加完 VFFT-inv 之后复跑实现，WNS 从 +0.262 掉到 +0.011
**复现**：`build/timing_zynq.rpt` 的前 14 条路径

---

## 症状

加完逆变换（`rv32_fft_bfly`，见 [087](087-split-intermediate-16bit-context.md)）
之后重跑 Zynq 流程：

| | 加逆变换前（10-06） | 加完之后 |
|---|---:|---:|
| WNS | +0.262 ns | **+0.011 ns** |
| DSPs | 128 | **142** |

失效端点仍然是 0（收敛），但余量只剩周期的 0.04%。

## 误判 —— 这部分比修法值钱

**我在 README 和台账里写下的是**：「这 0.251 ns 是本版加的逆变换吃掉的：
反向拆分与实数拆分共用 8 个复乘器，但四种符号组合现在要同时算出来再按模式选，
路径变长；DSP 也从 128 涨到 142」。

**这个结论是推的，而且没有任何测量支持它。** 我看到的只有两件事：
DSP 数涨了 14、WNS 掉了 0.25 ns。我就把前者当成了后者的原因。

**判据就在手边，我没打开**：`build/timing_zynq.rpt` 里明明白白列着最差路径的
源/目的地。打开一看 ——

```
Slack (MET) : 0.011ns
  Source:      .../u_steer/ramp_start_reg[3][0]/C
  Destination: .../u_steer/step_q_reg[12]/D
  Data Path Delay: 24.774ns  (logic 12.033 (48.6%)  route 12.741 (51.4%))
  Logic Levels: 28  (CARRY4=16  DSP48E1=2  LUT1=2 LUT3=2 LUT4=1 LUT5=1 LUT6=4)
```

**是波束转向块，不是 FFT 单元。** 前 14 条最差路径的归属：

| slack | 起点 | 模块 |
|---:|---|---|
| +0.011 / +0.018 / +0.059 / +0.065 / +0.083 / +0.094 | `ramp_start_reg[3][0]` | **`u_steer`** |
| +0.051 | `geo_q_reg[5][24]` | `u_steer` |
| +0.051 / +0.107 / +0.108 / +0.113 | `g_pipe[*].twq_reg` | `u_fft_bfly` |
| +0.055 / +0.063 … | CIC `acc_reg` / `comb_d_reg` | `u_pdm_rx` |

**7 条里 6 条是 `u_steer` 的 ramp 那一段**，而 `u_fft_bfly` 自己最差只有
**+0.051 ns** —— 它比 steer 那条还松 0.04 ns。所以"修 FFT 的拆分流水能救 WNS"
这句话是错的，按它去动手会白干一轮。

⚠ **0.251 ns 相对 10-06 的差目前归因不明**（那条路径 51% 是布线，可能是这次
改动的布局扰动，也可能是 §2 记过的跨次运行差异）。**要归因得把 RTL 回退到
HEAD 重跑一次做 A/B —— 还没做。** 在没做之前，不许再写"是逆变换吃掉的"。

## 根因

`rv32_steer_regs` 的渐变步长，从寄存器到寄存器**一拍走完**：

```
ramp_start_reg → 8 路相减 → 取绝对值 → 3 级 32 位比较树 → gap_max
              → 32×8 有符号乘法 → >>> 8 → step_w → step_q_reg
```

28 级逻辑、16 个 CARRY4，其中记一个 `net (fo=32)` 的 1.358 ns ——
`gap_max` 扇出到乘法的 32 位。布线占 51%。

## 修法

**把比较树挪到寄存器之前**：算 `gap_max` 用的那对值，从
`comp_tgt − ramp_start` 改成 `geo_q − comp_out`，中间压一级 `gap_max_q`。

**为什么一个数都没变**：`comp_tgt`/`ramp_start` 是在 **Q_FSM 那拍**从
`geo_q`/`comp_out` 装进去的，而 `Q_STEP` 在它的下一拍。所以
「`geo_q`/`comp_out` 在 Q_FSM 拍的值」与「`comp_tgt`/`ramp_start` 在 Q_STEP
拍的值」**逐位相同** ⇒ 算式等价，只是它现在跑在 Q_FSM 拍、结果在 Q_STEP 拍用。
**下游状态机一拍没多、也没少**（Q_FSM→Q_STEP→Q_RAMPW）。

改完两半各自有余量：前一半 = 相减+abs+3 级比较，后一半 = 乘法+移位。

**判据**（这次先量再改）：
- `tb_steer` / `tb_steer_regs` 都 PASS；
- 更硬的一条：把改动前后的 RTL 各跑一遍 `tb_steer_regs`，**输出逐字节 diff 为空**
  （渐变途中的中间样点数、走满后的 `comp[0]` 全一样）⇒ 行为没动，只动了时序。

**结果（2026-10-08 实测，`build/timing_zynq.rpt`）**：

| | 修前 | **修后** |
|---|---:|---:|
| WNS | +0.011 ns | **+0.170 ns** |
| 失效端点 | 0 | **0** |
| WHS | +0.051 ns | +0.021 ns |
| Slice LUTs | 22,062 | 21,981 |
| Slice Registers | 13,043 | **12,787**（−256 = 8 × 32） |
| DSPs | 142 | 142 |

- **FF 少 256 = 8 × 32**：`ramp_start` 那八个 32 位寄存器改完之后没人读了，被剪掉。
  这个数恰好对上，是"换源等价"的一个侧证。
- **约束换成了 `u_fft_bfly`**（+0.170，路径 `g_pipe[1].twq_reg[1]` → 写地址）。
  **`u_steer` 跌出前十** —— 原来它占 7 条。
- 修后的实得（+0.170）比事前推的（"上限 +0.051"）还好：布局整体重排了，
  FFT 那条也跟着松了。**推的上限不如重跑一次准。**

## 指纹

- **"资源数变了 ⇒ 关键路径就是它"是错的推理。** 资源涨落与关键路径位置之间
  没有因果关系，唯一能回答"关键路径在哪"的是 `report_timing` 的路径列表。
  这次差一步就照着错的结论去改 FFT —— 那会白干一轮，而 WNS 一点不动。
- 通用判据：**先看 `timing_zynq.rpt` 里起点/目的地的模块归属，再决定动哪里。**
  多条路径起点是同一个寄存器 ⇒ 那就是约束。
- 与 [081](081-function-division-synthesised-as-divider.md) 同类（都在"该看哪条
  路径"上做过错误假设），与 CLAUDE.md §0 的"先量再改"是同一条规矩的又一例。
