# 071 — VUPD 的增量是 `>>> 15` 不是 `>>16`（注释与代码差一倍）

**状态**：已修（2026-10-05）

---

## 症状

给阵列版 GSC 建模型时，按**源码注释**写了增量公式：

```verilog
// rv32_vec_unit.v:276-277
// VUPD 的逐元素增量：g（Q15）× x'（Q15）→ Q30，取高 16 位回到 Q15，
// 再左移 8 位对齐到系数的存储格式（Q15 + 8 个额外小数位）。
wire signed [31:0] gmul = $signed(scalar_q) * $signed(b2_q[b]);
wire signed [31:0] dq15 = gmul >>> 15;          // ← 是 15
```

注释说"**取高 16 位**"，我就写了 `(g·x) >> 16`。**代码是 `>>> 15`。**

后果不是"精度差一点"，而是**更新步长整整差一倍** —— 自适应滤波器用错一倍的步长，
要么收敛慢、要么直接发散。

## 怎么抓到的

在**真 RTL** 上给 `tb_gsc_vec_map` 加了一条**闭式**判据（不是比对模型，那会把同一个错误
抄两遍）：

```
系数全 0、样本全取 X0、g = G  ⇒  每个抽头 ΔC = (G·X0) >> k
                             ⇒  VRED = NT·ΔC·X0
取 X0 = 256、G = 256：若 k=16 → 120·1·256 = 30720
                      若 k=15 → 120·2·256 = 61440
```

**实测给出 61440** ⇒ k=15。一次就分开了。

## 误判（差点走错的路）

第一次跑出来是 **4096**，既不是 30720 也不是 61440。我第一反应是"VUPD 的索引错位"。
**不是** —— 是我自己的 TB **只推了 8 个样点**，而 FIR 跨 120 抽头，
绝大多数抽头读到的是"有效长度之外"的 0（RTL 的 valid 逻辑保证确定性零历史），
闭式的前提（所有抽头都读到 X0）根本不成立。推满 140 个之后才看出真相是 2 倍差。

**⇒ 闭式判据的前提要先自检**：它假设了什么？在这个 TB 里是"所有抽头都读到有效数据"。

## 根因

**注释写的是位宽（16 位），代码写的是移位量（15）。** 两者在 Q15×Q15→Q30 的语境下
正好差 1：`[30:15]` 是 16 位，但移位量是 15。作者按"位宽"措辞，读者按"移位"理解。

## 修法

三处一起改（口径的唯一出处是**模型**，固件与探针跟着它）：

| 文件 | 改动 |
|---|---|
| `scripts/golden/fw_gsc_vec_model.py` | `Array.vupd`：`>>16` → **`>>15`**；并且**回绕改饱和**（见下） |
| `sw/fw/fw_gsc.c` | `g = K<<11/nrm` → **`K<<10/nrm`**；K 的钳位界 `2^20` → `2^21` |
| `build/probe_nrm_for_vupd.py` | 门槛 `\|K\|/16` → **`\|K\|/32`** |

**顺带抓到的第二个错**（同一段代码）：写回是**饱和**不是回绕 ——

```verilog
assign c_wr_data[b] = updated >  33'sd8388607 ? 24'h7fffff :
                      updated < -33'sd8388608 ? 24'h800000 : updated[23:0];
```

我的模型写的是 `v &= 0xFFFFFF`（回绕）。⇒ 有效系数 `C_eff` 实际上**饱和在 ±32768（Q12）**。
这也是标量版（限幅 ±8192）与阵列版限幅不同的出处。

## 复现指纹

```bash
# 判据：g=x=256 时每个抽头 +2（不是 +1）⇒ VRED = 120·2·256 = 61440
wsl -e bash -lc "cd /mnt/d/.../zynq_-pl_-simd_-verilog && \
  iverilog -g2005 -I rtl -s tb_gsc_vec_map -o build/tb_gsc_vec_map.vvp -c scripts/filelist.f && \
  vvp build/tb_gsc_vec_map.vvp | grep VUPD"
#   → VUPD g=256: result = 61440   闭式期望 61440
#   → VUPD g=512: result = 122880  闭式期望 122880
```

## 教训

1. **注释里的位宽 ≠ 代码里的移位量。** 二者在 `[hi:lo]` 的写法下差 1，
   而这一处差 1 就是**步长差一倍**。**凡是"取高 N 位回到 Qx"这类措辞，去读代码那一行。**
2. **闭式判据要在真 RTL 上跑**，不是比对模型 —— 模型与固件会**抄同一个错误**，
   只有独立算出来的期望值能把它分开。
3. **先自检闭式的前提。** 这次第一版给 4096，根因是 TB 自己推的样点不够，
   不是 RTL 错 —— 差点往错的方向查。
