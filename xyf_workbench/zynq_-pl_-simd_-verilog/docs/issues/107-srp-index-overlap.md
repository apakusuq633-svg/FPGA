# 107 SRP 每格独占索引推进拍

状态：RTL 仿真与66对独立40MHz实现已修；完整 SoC 发布仍待验收。

**症状**：120 对 × 1024 格的 SRP 扫描实测 614400 拍；每格每对占 5 拍。

**误判**：模块旧注释认为同步 RAM 读依赖导致 5 拍不可减少。

**根因**：T0～T3 已完成读出、插值及登记写入，S_NEXT 的索引推进独占一拍；上一格的写入可以与下一格 T0 重叠。

**修法**：在 S_T3 登记写入并推进格/对；最后一格保留 S_NEXT，确保最后一次写入提交后才发布完成。保留单写口和全部小数位。更新两个现有 TB 的周期断言。

**复现指纹**：`bash scripts/test_srp_throughput.sh` 的 120×1024 为 491521 拍、66×1024 为 270337 拍；三次扫描/中断重启全部评分逐位相同。`tb_srp_scan` 的真实向量 1024/1024 一致，关闭插值后 1024/1024 改变。`tb_srp_regs` 核/PS 窗口一致，忙写反证通过。相同计数口径的前后数据及 12 麦待适配范围见 `docs/accelerator_optimization_12mic.md`。
