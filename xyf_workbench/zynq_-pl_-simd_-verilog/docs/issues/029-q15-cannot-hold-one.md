# 029 Q1.15 装不下 1.0 —— 单位增益静默反相

**状态**：已修
**日期**：2026-09-22
**阶段**：Stage 1（通道增益校准）
**复现**：`tb/tb_chan_align.v` 第 5 段

---

## 症状

`rv32_chan_align.v` 的增益系数按 **Q1.15** 定义（1.0 = 32768）。TB 里灌 1.0
（也就是想让信号原样通过），结果：

```
DC 残差 @100 拍  实测 -80993      解析 +82260
```

**输出被反相了**，而且幅度几乎不变 —— 所以看频谱、看 RMS、看相关峰位置
**统统看不出来**，只有拿绝对符号去比才露馅。

## 误判

第一反应是 DC 高通接错了（符号反了），因为残差出现在 DC 通路上。
差点去改 `y[n] = x[n] − x[n−1] + ...` 那一行。

**不是。** 把增益设成 0.5 时输出正确减半（+50048 vs 期望 50045），
说明 DC 通路是好的，问题只在 g = 1.0 这一点上。

## 根因

**Q1.15 的数值范围是 [−1, 1)，表示不了 1.0。**

| 想要的 | 写进去的 16 位 | 按有符号解释 |
|---|---|---|
| +1.0 | `16'h8000` | **−1.0** |

`16'h8000` 是 32768，超过了 16 位有符号的上界 32767，于是被解释成 −32768，
即 −1.0。乘以它等于 **把信号反相**。

这是定点设计的经典陷阱：**Q1.15 能表示的最大值是 1 − 2⁻¹⁵，不是 1**。

## 修法

增益系数改用 **Q2.14**（1.0 = 16384，范围 [−2, 2)），乘法结果右移 14 位。

```verilog
wire signed [15:0] g = gain_q_i[gi*16 +: 16];   // Q2.14
assign gprod[gi] = y_acc_q[gi] * g;
wire signed [ACC_W+15:0] sh = gprod[gi] >>> 14;
```

选 Q2.14 而不是无符号 UQ1.15 的理由：**Verilog 里混用有符号和无符号会把整个
表达式变成无符号**，那是个更难查的坑。Q2.14 全有符号，行为明确。

## 连带修正

同一段里还有两个 TB 自身的坑，一并记下：

1. **`check()` 的消息必须是 ASCII**。UTF-8 中文经 `reg [8*72-1:0]` 位向量传参会
   按字节截断，长消息在 `$display` 里显示成乱码 —— 而乱码的 FAIL 等于没有信息。
   中文只能出现在 `$display` 的字面量里。
2. **不能用平方比大小**：`r1*r1` 里 80993² = 6.6e9 溢出 32 位 integer，
   翻成负数后断言会假通过或假失败。比绝对值。

## 复现指纹

```bash
wsl -e bash -lc "cd .../zynq_-pl_-simd_-verilog && \
  iverilog -g2005 -I rtl -s tb_chan_align -o build/tb_chan_align.vvp -c scripts/filelist.f && \
  vvp build/tb_chan_align.vvp"
```

把 `>>> 14` 改回 `>>> 15`、TB 的 `16'd16384` 改回 `16'd32768`，
第 2 段残差会从 **+80993** 翻成 **−80993**。一个字都不差。

## 留下的教训

- **"单位增益"是最该单独测的一档**，不能因为"乘以 1 应该没事"就跳过。
  实测里它恰好是唯一出错的一档，而 0.5 那一档是对的。
- 这个坑**看波形、看频谱、看 RMS 都发现不了**（幅度几乎不变）。
  只有**逐点比符号**才行 —— 所以 §39 那条"禁止 PC float 直接对 HDL"是对的，
  中间那层定点模型放在这里也未必抓得到（定点模型如果用 Python float 存系数，
  根本不会溢出）。**真正抓住它的是「灌已知值 + 比绝对值」这个 TB 做法。**
