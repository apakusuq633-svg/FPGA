# 054 POP 预取的钳位打在错误的指针上 ⇒ 只错最后一个 bin

**症状** 把 `rv32_fft_bfly` 的存储换成 BRAM 之后（[053](053-fft-storage-not-inferred.md)），
`tb_fft_bfly` 报：

```
  首个不符: bin 511 实测 re=-111 im=11 期望 re=-107 im=-139
  bin 比对: 1/513 条不符
```

**513 条里恰好错 1 条，而且是最后一条。**

**误判** 这个现象第一眼是指向**拆分阶段**的：bin 511 是拆分里 `k=1` 那一次写出的
镜像条（`X[512−1]`），所以自然会去看镜像写回、看 `two_out`、看最后那对
`a_we`/`b_we` 有没有撞车。也想过会不会是 Nyquist 那一路（`nyq_q`）串了。

**都不对**：bin 512（Nyquist，走单独的寄存器）是对的，bin 0..510 也是对的，
**只有「数组里编号最大的那条」错** —— 这个形状说明问题不在算法，在**取回通路**。

**根因** BRAM 读有 1 拍延迟，所以 POP 从「组合读」改成**提前一拍出地址**的预取：
某一拍出的地址，必须是**下一拍才成为当前值**的那个指针。
我按「当前指针 ≥ 511 就钳到 0」写：

```verilog
wire [8:0] pop_radr = (ptr_q >= 10'd511) ? 9'd0 : (pop_fire ? ptr_idx+1 : ptr_idx);
//                    ^^^^^^^^^^^^^^^^^^^ 错在这里
```

`ptr_q == 511` 那一拍 **POP 还没发生**，此时该出的是 511 自己的地址；
钳到 0 就把 511 的预取冲掉了，下一拍读回来的是 bin 0。

**指纹** **513 条里只错最后一条，且错的不是 512（Nyquist）而是 511**
⇒ 问题在 POP 的预取/钳位，不在蝶形也不在拆分。
（顺带：这个错法在别的模块里未必看得出来 —— 前 512 条全对。）

**修法** 钳位要对**下一指针**判，不是对当前指针判：

```verilog
wire [9:0] pop_nxt10 = pop_is_nyq ? 10'd0 : (pop_fire ? ptr_q + 10'd1 : ptr_q);
wire [8:0] pop_radr  = (pop_nxt10 >= 10'd512) ? 9'd0 : pop_nxt10[8:0];
```

`pop_is_nyq` 那一拍下一指针本来就是 0（Nyquist 不占数组，绕回 bin 0）；
只有 `ptr = 511` 且发生 POP 时下一指针才是 512，那一拍读什么都不会被用到
（下一拍返回的是 `nyq_q`），钳成 0 正好把绕回要的 bin 0 预取上。

改完 **513/513 逐位一致**。

**复现** `tb_fft_bfly` 的 `bin 比对` 那一行。
