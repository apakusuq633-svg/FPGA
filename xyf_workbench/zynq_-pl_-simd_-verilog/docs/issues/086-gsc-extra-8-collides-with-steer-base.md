# 086　`EXTRA(8)` 越界一个字，正好踩在 `FW_STEER_BASE` 上

**症状**　`tb_fw_gsc` 打印 `[阵列] 探针 EXTRA[8] = 最后跑到的样点号`，在 §9 还没跑起来时
读出来是 **511**（正确）；等 §9 能跑了之后，同一个地址会变成 **3**（= `STEER_RES_STATUS`）。
`tb_fw_steer_probe` 早期把 `STATUS` 读成 **511**，正是同一处的另一半。

**误判**　一度以为"转向结果块里的 STATUS 没人写"或"壳的 STATUS 寄存器坏了"。
其实是**两个写者抢同一个字**。

**根因**　`FW_GSC_EXTRA = FW_GSC_BASE + 0x380 = 0x3C40`，而 `FW_STEER_BASE =
FW_GSC_BASE + 0x3A0 = 0x3C60`。两个定义之间只隔 **0x20 = 32 B = 8 个字**，
所以扩展块合法下标是 **0..7**。

但 `sw/fw/fw_gsc.c:188` 的进度探针写的是 **下标 8**：

```c
EXTRA(8) = n;   /* 进度探针：卡住时能看出走到第几个样点（这次抓 072 就靠它） */
```

`EXTRA(8)` = `0x3C40 + 32` = **0x3C60 = `FW_STEER_BASE + 0`** = `STEER_RES_STATUS`。
`fw_mem.h` 里把转向块说成"从 .fwgsc 尾巴里空着的 8 个字抠出来的"——
那句话对 `[0..7]` 成立，但 072 那次加进度探针时用掉了第 9 个字（下标 8），
**把那 8 个空位的第一格提前占了**。两处改动各自都合理，撞在一起没人发现。

**修法**　（**未做**）二选一：

- 把进度探针挪出这块：`fw_mem.h` 里给 `FW_GSC_EXTRA` 显式声明 9 个字，
  转向块整体后移 4 B（`FW_STEER_BASE = FW_GSC_BASE + 0x3A4`），
  并同步 `link.ld` 的 `.fwgsc` 长度 —— 牵地址，风险大；
- 或把进度探针塞进 `[0..7]` 里某个闲置位（例如与 `[4]` 场景计时共用低 10 位），
  不动任何地址 —— 风险小。**推荐这条。**

**复现/指纹**　一个地址两个写者，认法是**同一个字在不同 TB 里读出不同的值**：
`tb_fw_gsc` 说 511、`tb_fw_steer_probe` 说 511（§9 没跑）/ 3（§9 跑了）。
只要看到 `FW_STEER_BASE + 0` 出现过 0..511 之间的数，就是它，不是壳的问题。

## 实测确认（2026-10-06 21:28）

不再只是静态推断。装好转向 LUT、§9 能跑完之后，`tb_fw_gsc` 的输出里出现：

```
[阵列] 探针 EXTRA[8] = 最后跑到的样点号 = 3
```

**3** 就是 `STEER_RES_STATUS`（`fw_steer.c` 里 §9 查询成功 + 块已 LOCKED 时写的值）。
这一路本该报 **511**（整趟跑满的样点号），现在被 §9 覆写掉了。

- 该行在 `tb_fw_gsc` 里**只是 `$display`，没有 `check`** ⇒ 它不会因此变红，
  但它已经把「同一个字两个写者」从纸面推断变成了**跑出来的事实**。
- 反向的一半在 `tb_fw_steer_probe`：早期把 `STATUS` 读成 **511**，
  也是这个字被阵列那路最后写进去的值。
