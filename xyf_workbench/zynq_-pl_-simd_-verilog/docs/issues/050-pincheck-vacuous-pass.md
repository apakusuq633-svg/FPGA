# 050 引脚核查报了个假 PASS —— 查不到值，空对空永远"相等"

**背景** 核心板从 `XC7Z010` 换成 `XC7Z020`。整套 xdc 里的 `PACKAGE_PIN` 是从核心板
原理图 PDF 抽出来的（不是 Vivado 报的），所以必须先回答一个问题：
**同一封装（CLG400）下，bank34/35 的脚位在两个器件上是不是一样？**
如果不一样，现有 xdc 会**照常编译、照常出位流，只是全部接错脚** —— 上板现象是
「什么都不动」，跟没插电一样。

**症状（第一版）** 脚本跑完输出：

```
PART  xc7z010clg400-1  查不到 19 个脚
PART  xc7z020clg400-1  查不到 19 个脚
E19    aud_mclk_o    **查不到**   **查不到**   同脚 OK
...
PASS: 两个器件在 CLG400 下这些脚位完全相同 —— 现有 xdc 可以直接用
```

**19 个全查不到，却报 PASS。** 而那一行 `同脚 OK` 每一格左边右边都是同一串
`**查不到**` —— 两个空值比较当然相等。

**误判** 差一点就信了：结论（"xdc 可以直接用"）恰好是我希望看到的，
而且脚本自己打印了 PASS。**这个坑的形状和 042 里那个
`(ref−got) mod 2^w == 0` 一模一样：回绕版恒满足它，所以位宽怎么扫都"通过"。**
同一个模式在同一个仓库里出现了两次。

**根因** 两层，叠在一起：

1. **`get_package_pins` 必须先 `link_design`。** 只 `create_project -in_memory`
   会抛 `[Common 17-53] No open design`，被 `catch` 吞掉之后返回空 → 记成"查不到"。
2. **catch 把异常变成了空值，而空值参与比较是合法的。** 于是失败被
   静默降级成"数据"，再被拿去算出一个看起来正常的结论。

**修法** 三条一起：

- 先 `link_design -part $p`，再用 `get_package_pins`；
- 站点名在 **`PIN_FUNC`** 属性里（形如 `IO_L20N_T3_34`）——
  `package_pin` 对象**没有 `SITE` 属性**，查它会抛异常，同样被 catch 吞成空；
- **加一条"有效性"判据排在最前面**：只要有任何一格是「查不到」，
  直接 `INVALID: 这次比较不作数` 并 `exit 1`，**不许走到 PASS 那一条**。

**结果（修完之后，这次是真的）**

```
PART  xc7z010clg400-1  : 19 个脚里 0 个查不到
PART  xc7z020clg400-1  : 19 个脚里 0 个查不到
N18 → IO_L13P_T2_MRCC_34   （两个器件相同，与 board_io.md 的锚点吻合）
V16 → IO_L18P_T2_34        （两个器件相同）
... 19/19 同脚
PASS: 两个器件在 CLG400 下这 19 个脚位完全相同
```

**复现指纹** **「全部一致」这个结论，先看每一格是不是真的取到了值。**
凡是「查不到 / 空 / 异常」被 catch 吞掉之后还参与比较的判据，
都必须先单独判一次有效性 —— 空对空永远相等。
