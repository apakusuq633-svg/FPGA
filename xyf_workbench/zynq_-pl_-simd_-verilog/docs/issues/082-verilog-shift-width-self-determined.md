# 082　移位表达式的宽度由左操作数决定 ⇒ 乘以 2^16 的那一项静默变 0

**症状** `tb_steer` 段 1 报 1840 处不符，而**错的值有规律**：

```
grid 0 ch 0  got=0x00000000 exp=0x00012000   (0 vs 73728)
grid 0 ch 1  got=0x03fee000 exp=0x00000000   (67035136 vs 0)
grid 0 ch 2  got=0x00000000 exp=0x00012000
...
```

规律是 **`got = exp − 73728`**（除 ch1 外），而 ch1 **正好是该取到 min 的那一路**。
看上去像"求 min 漏了一路"，或者"打包/还原的整数字段错了"。

**误判** 先怀疑几何流水的时序：`tmin` 是不是拿被覆盖前的旧值比的？
（那条我确实写错过一次，见下面"曾经真错过的那个"。）改完时序症状不变。

**根因** **Verilog 的移位宽度规则**：

```verilog
wire signed [9:0] idx_s = lut_r[13:4];              // 10 位补码，值 −2
wire signed [31:0] tau_w = ($signed(idx_s) <<< 16)  // ← 这一项恒为 0
                         + (frac <<< 12);
```

`a << b` 的结果宽度取**左操作数**的宽度（10 位），不是右侧上下文给的目标宽度。
把 10 位的值左移 16 位 ⇒ **所有有效位都被移出**，结果恒 0。
所以 `tau_w` 里只剩 `frac << 12` 那一项。

指纹就在 `got` 里：`0x03FEE000 = 0x3FEE << 12`，而 `0x3FEE` 正是该条目的**打包值**
（`idx=0x3FE` 即 −2，`frac=0xE` 即 14）。**值里含着一个"看着像下标的东西"** ——
这就是这个坑最好认的样子：不是随机错，而是公式里少了一项、多的那项带着打包值的味道。

**修法** 先显式符号扩展到 32 位，再移位：

```verilog
wire signed [31:0] idx_w = {{(32-IDX_W){idx_s[IDX_W-1]}}, idx_s};
wire signed [31:0] tau_w = (idx_w <<< 16) + $signed(frac_w <<< 12);
```

回归：`tb_steer` 段 1 **256 格 × 8 路 0 错**，两个反证段（改 LUT 输出必变、
不同格点 comp 必不同）仍通过。

**曾经真错过的那个（同一趟查出来的第二处）**
`tmin` 原本写成 `(tau_q[m_q] < tmin_q) ? tau_q[m_q] : tmin_q` ——
`tau_q[m_q]` 在这一拍**正被 `tau_w` 覆盖**，比的是上一个格/上一路的值。
必须直接比刚读出的 `tau_w`。两处都改完段 1 才归零。

**复现/指纹** 「结果是 `期望值 − 某个常数`，或值里带着**打包格式的痕迹**」——
先查**位宽**（拼接、移位、赋值截断），别查算法。
⚠ 与 [077](077-srp-r-row-length-tied-to-n-grid.md) 同族：**都是"写下来的表达式
和它实际算的东西不是一回事"**。
