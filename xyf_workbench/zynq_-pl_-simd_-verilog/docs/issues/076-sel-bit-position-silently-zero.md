# 076　ADDR 的 SEL 位放错位置 ⇒ 所有写静默落进第一个数组

**症状** 新写的 `rv32_xsp_regs` 窗口，灌完 XI/XJ 之后回读 Ψ **全是 0**；
同时「保留值 SEL=3 必须置 WERR」这条反证**不成立**（WERR 恒 0）。
`inband_cnt` 却正好是 205 —— 说明推流 FSM 与限带掩码都是好的，只有数据是空的。

**误判** 先怀疑推流 FSM 的时序（`in_valid` 是不是漏推了第 0 个 bin），
再怀疑缓冲没写进去。查了两轮才发现 XI 的缓冲**确实**被写了 ——
写进去的是 XI 和 XJ **两份数据叠在同一个数组上**。

**根因** RTL 读 `wdata[17:16]` 当 SEL，而 TB 那边拼的是
`{14'd0, sel, 22'd0}` —— SEL 落在 bit[23:22]。赋给 32 位值后**截断**，
bit[23:22] 被丢掉 ⇒ SEL 恒为 0 ⇒ 每次 WDATA 都写 XI。XJ 恒 0 ⇒
Ψ = X_i·conj(0) = 0。**全程不报错**，只是每个数都错。

两个 wrapper 都有这个问题，而且位域中间还留了空洞（IDX 15 位占 `[14:0]`，
SEL 却在 `[17:16]`，bit15 空着）—— 谁照着"拼一个值写进去"都会踩。

**修法** 两处统一成 **IDX 在低位、SEL 紧挨其上、中间不留空洞**：
SRP `[16:15]`/`[14:0]`，XSP `[11:10]`/`[9:0]`，读回也按同一布局。
TB 侧加一个 `ad(sel, idx)` 函数专门负责打包，不再手拼。

**复现/指纹** 「窗口读回来全是 0，但状态位 / BUSY / DONE 都对」——
状态对、数据空，先查**地址打包**，别查数据通路。
第二个指纹：**某条反证不成立**（保留值没报错）。反证不成立常常意味着
"你以为在测 A，其实一直在测 B"（这里：以为在写 XJ，一直在写 XI）。
