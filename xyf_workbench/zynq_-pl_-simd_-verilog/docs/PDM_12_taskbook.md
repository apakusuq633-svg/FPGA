# ZYNQ 12 麦三正交面阵列：开发与验证任务书

**版本：** V1.0（2026-10-14）  
**适用范围：** ZYNQ PL 内 RV32 软核、12 路 PDM 音频采集、GCC-PHAT / SRP 声源定位、DAS/FIR 定向增强。  
**文档性质：** 待办与验收计划，**不是**已经完成的代码审计或实板测试报告。

> **核心决策：** 在麦克风的具体位置、面内排列及通道映射未知时，仍可继续采集、预处理、FFT/GCC 数值正确性与性能优化；但不得把假设坐标当作真实阵列配置，也不得宣布完整 12 麦三维定位已通过验收。

## 1. 已知条件与尚未确认的信息

### 1.1 用户已确认的结构

- **12 个麦克风**，分布在**三个相邻且两两互相垂直的面**上。
- **每个面 4 个麦克风**，共 3 × 4 = 12 个。
- 可以为软件建模临时定义局部三维坐标系，但**坐标原点、各面的朝向、面上 4 麦的排列形式均未确认**。
- 所有 12 麦两两组合共有 **C(12,2)=66 对**，其中同面 3 × C(4,2)=18 对、不同面 48 对。66 对是组合数量，不代表当前固件已经全部执行。

### 1.2 暂时未知，禁止自行假设为事实

1. 三个面的实际长宽、相对位置与公共交线/顶点的安装关系。
2. 每个面 4 麦的排列（2×2、一字、其他）、精确中心坐标及最小/最大间距。
3. 12 根输入的数据通道编号与物理麦克风编号对应关系。
4. 阵列正前方、水平角/俯仰角零点、坐标轴正方向及声源定位的有效角度范围。
5. 真实板级时钟同步、采集一致性、线缆与电气验证结果。

**约束：** 如为算法单测需要引入“测试几何”，必须命名为 `TEST_GEOMETRY`（或等效测试配置），与正式生产参数隔离。不得用测试几何代替实物坐标做性能或精度宣称。

## 2. 当前工程与性能基线（按已有记录，未经本次重新运行）

| 项目 | 已知值/最新记录 | 口径说明 |
|---|---:|---|
| PL / RV32 时钟 | 40 MHz | 当前提供的工程配置 |
| PDM 时钟 | 2.5 MHz | 40 MHz ÷ 16 |
| CIC 抽取倍数 | 64 | PCM 采样率 39,062.5 Hz |
| 帧长度 | 每路 1024 PCM 点 | 12 路合计 12,288 点 |
| 音频采样窗口长度 | 26.2144 ms | 1024 ÷ 39,062.5 |
| 采集读 MMIO 次数 | 12,288 → 6,144 次 | 已报告使用两个 16 位样点/32 位字的成对读取 |
| Capture + 原始统计 | 13.35 → 9.46 ms | 已报告下降约 29.1% |
| 计时版五段合计 | 30.62 → 26.69 ms | 已报告下降约 12.8%；不等于完整定位闭环耗时 |
| GCC 相关回读 | 每对 1024 点 → 32 点相关环 | 已报告为减少 SRP 无关数据传输 |
| PHAT | 接入生产 SIMD 通路 | 已报告修复弱频点数值问题；仍需 12 麦全链回归 |

**重要边界：** 这些收益来自截图所述的合并后 RTL 仿真与远端记录。原始性能报告属于**合成 PCM + RTL 仿真**，不是物理麦克风或 PS Cortex-A9 实板计时。应核对 `build/das12_profile/summary.json`、仿真日志和当前提交版本是否完全对应；尤其确认“几何未知时跳过没有消费者的 FFT/频谱缓存”后，26.69 ms 实际包含哪些处理段。

**历史参考，不可直接迁移：** 之前记录的 8 麦定位计算加速约 1.52 倍、更新率 10.15 → 13.55 Hz，是 **8 麦配置的仿真收益**，不是 12 麦三维定位的已测结果。

## 3. 必须先区分的两类实时要求

- **连续音频路径：** 12 路 PDM → CIC/PCM → DAS → FIR → 音频输出。需要跟上 PCM 样点节拍，重点检查连续输出、`drops`、FIFO 与音频处理最坏周期。
- **定位快照路径：** 稳定快照 → RV32 读取 → 预处理 → FFT → GCC-PHAT → SRP → 更新指向。是否要求每 26.2144 ms 必须定位一次，**目前未确认**。若允许跳过定位快照，单次定位耗时超过音频窗口不自动代表连续音频失效。

**算术核对：** 26.69 ms 比一个 26.2144 ms 采样窗口多约 **0.476 ms（1.8%）**；仅在“每个窗口都必须对应一次完整定位，且无重叠”的约束下才构成直接超时。当前完整 66 对逆变换尚未验证，这个数字不能用于最终实时性验收。

## 4. 分级问题与执行计划

### P0-1｜版本、计时范围与基线存档（立即执行，不改功能）

**待解决：** 优化前后的数据口径、测试分支、编译插桩是否一致；新版本是否跳过 FFT。

**行动：**

1. 记录仓库 commit、固件/RTL 构建宏、仿真入口与测试时间。
2. 运行 `wsl python3 scripts/check_cycle_profile.py`，保存摘要和完整日志；打印 `RESULT(5)` 并核对五段周期和。
3. 列出实际运行的 capture、prepare、push、run、pop，明确是否执行 12 路正向 FFT、66 对互谱与 IFFT、SRP 和转向更新。
4. 向 `docs/measurements.md` 追加「数值／怎么量／口径」三项；记录插桩模式对指令及寄存器分配的影响。

**完成标准：** 可以凭同一个 commit 与命令复现最新 26.69 ms 的测量范围，不出现“未运行却算入完整链”的表述。

### P0-2｜12 麦阵列几何接口（先做框架，等待实测坐标）

**待解决：** 当前只有三面拓扑，没有每个麦的三维坐标。

**行动：**

1. 设计统一几何输入：`mic_xyz[12][3]`、`channel_to_mic[12]`、坐标单位和方向定义。
2. 建立三面分组元数据：`face_id` / `mic_id`，只填已知的每面数量；实际编号待确认。
3. 为 66 对 `(i,j)` 自动生成组合表，避免手工遗漏/重复。
4. 增加几何有效性检查：坐标缺失时禁止正式 SRP 方向输出、自动转向和“定位成功”标志。
5. 可使用独立测试几何验证 API 和算法，但不得写进正式默认配置。

**完成标准：** 几何未知时系统明确报告 `geometry_enabled=0`（或等效状态）；采集和独立 FFT/GCC 测试仍能运行，不输出伪造的真实角度。

### P0-3｜66 对 GCC-PHAT 计算链的独立正确性与周期验证

**待解决：** 全部 66 对 IFFT 尚未出现在已确认的生产测量中。

**行动：**

1. 用已知的 12 路同步合成 PCM 数据验证 12 路频谱生成、缓存生命周期与覆盖边界。
2. 遍历全部 66 对，逐对核对互谱、PHAT、逆变换和相关峰；与标量/离线黄金模型比较。
3. 核查 SIMD PHAT 的零值保护、弱频点、定点舍入/饱和、正负频率与共轭对称性。
4. 对比完整 1024 点相关结果与回读 32 点相关环；明确相关环的实际时延索引集合及环绕顺序。
5. 单独统计 12 路正向 FFT、66 对互谱/PHAT、66 对逆 FFT、回读与 SRP 的周期；记录峰值 scratch/DTCM 用量。

**完成标准：** 66 对执行计数、黄金数值误差、内存越界检查、每段周期完整记录。此阶段可以不宣称真实声源方位角正确。

### P0-4｜32 点相关环的几何适配安全检查

**待解决：** 32 点是否覆盖所有真实麦克风对的可能时延，目前**不能确定**。

**行动：**

1. 从 RTL/固件实际实现提取 32 点对应的正、负整数采样滞后范围，不能默认它必然是 `[-16,+15]`。
2. 几何坐标到位后，对每对计算最大时延样点数 `ceil(distance(i,j) × Fs / c)`，与环的支持范围比较。
3. 检查相关环的负下标、模 1024 映射、峰值附近插值及越界保护。

**参考换算：** 在 `Fs=39062.5 Hz`、声速暂取 `343 m/s` 时，1 个 PCM 样点代表约 **8.78 mm 的声程差**；这个数只是解释时延范围，**不是**阵列实际麦间距。

**完成标准：** 任意生产 SRP 查询时延必须落在有效回读范围；否则扩大回读窗口或改变策略，不能静默截断。

### P1-1｜继续诊断采集剩余 9.46 ms

**待解决：** 成对读取已减少总调用数，但 CPU 采集/统计仍占用较多周期。

**行动：**

1. 在固件中分离 READY 等待、INDEX/DATA MMIO、拆包、原始统计和存数组的周期。
2. 用 `riscv64-unknown-elf-objdump -d build/das12_profile/fw/fw_live12.elf` 检查采集热点循环和意外函数调用；实际产物路径以仓库为准。
3. 核实 `rv32_pdm_capture.v` 的 DATA 读取自增副作用及总线应答周期，排除重复 INDEX 写入或同字二次读取。
4. 先尝试固件级循环整理/展开；任何修改都须对比 12 路 PCM 样本的逐字一致性与快照所有权协议。

**完成标准：** 给出“为什么需要当前周期”的逐类构成，以及改前、改后表；不能把全部差额简单归罪于 MMIO。

### P1-2｜预处理 DC/定标/Hann 逐段量化优化

**待解决：** 原五段基线中 prepare 为 599,613 拍（约 14.99 ms），曾是最大单段之一；新版本的 prepare 数字需要重新读取。

**行动：**

1. 分别测量 DC 统计、去直流、定标、Hann 加窗、数据格式转换与中间写回。
2. 调查能否合并遍历并重用缓存，先减少冗余访存，再考虑 8 lane SIMD。
3. 检查 SIMD 与持续 DAS/FIR 的资源仲裁，避免局部提速破坏连续音频。
4. 用同一输入比较处理前后 FFT 输入的误差、饱和率和结果一致性。

**完成标准：** prepare 的真实周期改善可复现；定位数值和连续音频回归不退化。

### P1-3｜多帧与端到端实时性

**待解决：** 尚无完整 12 麦三维定位更新频率和真实连续运行验证。

**行动：**

1. 连续运行多帧，分别记录“声学采样帧”“已发布快照”“被消费快照”“定位更新”四种计数。
2. 读取 READY、SEQ、FIRST、ACKSEQ、RELEASE、`drops` 和缓冲/FIFO 状态；明确允许丢弃的究竟是定位快照还是音频样点。
3. 记录 12 麦完整链的平均、最大周期、帧间隔、定位更新率；避免只测单帧通过。
4. 对方向更新前后检查 DAS/FIR 输出连续、音频 FIFO 不因定位造成非预期溢出。

**完成标准：** 实测给出完整链处理时长、定位更新率、音频最坏周期、丢弃计数，并与书面实时需求比较。

### P2｜VFFT 块搬运（暂缓）

**待解决：** CPU 发起每字 PUSH/POP 的开销是否还值得用 RAM B 口和新自定义指令消除。

**决策：** 不以历史 6.5% 的搬运占比作为当前版本的当然结论；待完整 66 对和前面优化重新测量后决定。只有当 FFT/搬运已成为高占比热点，且收益足以抵消 RTL、时序和验证风险时才实施。实施前重跑 Vivado 的资源及 WNS/WHS。

## 5. 推荐的两阶段验收门槛

| 阶段 | 当前就能完成 | 必须留待实际几何/实板 |
|---|---|---|
| A：无几何数值/性能验收 | 12 路采集一致性、12 FFT、66 对 GCC-PHAT/IFFT 数学正确性、采集/预处理性能、多帧音频连续性 | 不输出真实三维方向；不宣称阵列定位精度 |
| B：几何确认后的完整验收 | 将实测坐标写入统一配置、核对 32 点相关环、启用 SRP/自动转向、重新测整帧和更新率 | 真实声源方位角/俯仰角误差、室内反射与噪声场景、物理麦克风/板卡长期稳定性 |

## 6. 对远端开发助手的执行指令

> **请先执行 P0-1，再按 P0-2、P0-3、P0-4、P1-1、P1-2、P1-3 的顺序推进。** 当前仅知阵列为三个相邻且两两垂直的面、每面 4 麦，面内排列和三维坐标未知。禁止虚构几何、通道映射或真实定位精度。允许单独用带明确标识的测试几何做算法验证，但正式定位输出必须有几何有效性门控。先测后改；每项提交“修改文件/根因/测试命令/周期前后对比/功能回归/剩余风险”。在真实 66 对工作量测定前，不实现 VFFT 块搬运。任何 RTL 修改要重新核查 40 MHz 时序与 WNS/WHS。

## 7. 每项工作统一交付格式

1. **状态：** 未开始 / 诊断中 / 已修改未验收 / 已验证。
2. **证据：** commit、命令、日志路径、仿真场景或实板环境。
3. **数值：** 优化前、优化后、帧级占比、实际加速比；不得混用 8 麦、12 麦或不同插桩构建。
4. **功能：** 黄金模型误差、`LIVE12_SOC_PASS`、序号连续性、`drops`、端到端更新率。
5. **口径：** 合成 PCM / RTL 仿真 / FPGA 实板 / 解析估算，以及是否含 66 对逆变换、SRP 和等候时间。
6. **下一步：** 已解决问题、阻塞原因、必须由用户补充的物理资料。

## 8. 需要用户未来补充的最小信息（目前可以空缺）

- 三个面的实际照片或装配草图（标注哪一面为正面）。
- 每个面 4 麦的中心位置和尺度，最好以毫米给出。
- 12 个物理麦克风与输入 DIN/通道编号的映射。
- 预期定位输出是仅水平角，还是水平角 + 俯仰角。
- 对定位更新频率及原始快照跳帧的实际要求。

**最终原则：** 先证明“12 麦数据链正确、66 对数学运算正确、周期账能对上、连续音频稳定”，再用真实三维坐标完成“方向正确、定位稳定、自动转向有效”的验收。
