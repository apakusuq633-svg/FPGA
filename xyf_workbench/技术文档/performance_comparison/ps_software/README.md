# PS算法的Windows宿主性能实测

该目录只测试Windows x86-64宿主程序，不连接板卡，不修改生产源码，不代表Cortex-A9、ARM NEON或FPGA的实际耗时，也不构成PS-only、PS+PL标量、PS+PL向量三架构的统一加速比。

正式主表来自`measured_20261028_host_quiet/results.json`。首轮`measured_20261028_host`作为并发环境记录保留；两个`smoke_run*`为调试产物，不用于正式数据。首次烟雾失败由测试包装读取反馈字段偏移错误导致，已更正并完成后续全部数值和统计复核，未更改生产算法。

## 运行

在工作区根目录执行：

```powershell
& C:/msys64/ucrt64/bin/python.exe performance_comparison/ps_software/run_benchmarks.py
```

默认每种搜索模式/场景41次、除法模式101次、包络模式31次；各模式先有一次验证调用，再有5次预热，均不计入统计。每一测量轮以固定随机种子打乱变体顺序，避免所有基线或优化模式都固定先执行。新结果自动保存至本目录`run_<UTC>`，不会覆盖旧记录。

可用参数：`--output 本目录内尚不存在的新目录`、`--search-repeats 41`、`--division-repeats 101`、`--envelope-repeats 31`、`--warmup 5`、`--skip-envelope`。计时开始后不要同时进行综合、编译或其他重负载；Windows仍可能有调度尾延迟，脚本不删除离群值。

```powershell
& C:/msys64/ucrt64/bin/python.exe performance_comparison/ps_software/verify_results.py performance_comparison/ps_software/measured_20261028_host_quiet/results.json
```

验证脚本重算CSV统计、核对工具/输入/产物/源码哈希、比较搜索输出并用Python整数重算商，不重新计时。

## 正式结果

CPU为Intel Core Ultra 5 338H，Windows 11，GCC 16.2.0，Python 3.14.8；C使用`-O2`，未启用`-ffast-math`或`-march=native`。计时使用C内部QueryPerformanceCounter，排除Python/ctypes入口、文件读写、进程启动、输入生成与编译。缓存为预热后稳态，不强制清缓存、不锁CPU频率；这不是实时操作系统的最坏执行时间证明。

单位均为毫秒。加速比采用同夹具参考均值/该模式均值。

调用当前`c9_candidates_search()`，使用当前生成镜像中的九路转向LUT，并由构建器只读核对其与当前非均匀声孔坐标配置一致。每场景固定16640×9原始PCM、156250 Hz、三频带、36麦对、1024方向格。参考宏为`C9_REFERENCE_SEARCH_INTERPOLATION`和`C9_REFERENCE_SEARCH_IFFT`，各模式只改变现有参考开关，不改变质量门控。

单宽带输出1个候选，三源分频混合输出2个候选。四模式公开反馈均61个uint32逐字相同，全部3072个整数方向评分相同；最后处理频带的2304个相关double最大误差分别1.11e-16和8.33e-17。计时结果不证明三源均被发现或分类成功，不包括历史复制、DMA、排队、GSC、诊断和HTTP。

| 其他专项/模式 | 重复 | mean | p50 | p95 | max |

| 131072次商/原生signed64除法 | 101 | 0.3520 | 0.3460 | 0.4379 | 0.7499 |
| 131072次商/生产共享倒数与精确修正 | 101 | 1.5140 | 1.4035 | 2.0928 | 4.4608 |

| 包络/当前C9F2单次4096前端 | 31 | 2.0698 | 2.0553 | 3.0238 | 3.4675 |

除法专项使用4096个运行时变化的正分母，每个分母32个有符号分子，与生产NLMS范围对应。两路径与Python任意精度向零除法131072项精确相同。在本机x86-64上，共享倒数耗时更长，原生/共享均值比约0.2325；该负收益完整保留。共享倒数针对ARM32软件64位除法设计，此测试不能推导A9收益，也不是完整GSC吞吐测量。

包络使用同一40000点、39062.5 Hz、600 rpm解析AM输入。历史前端为1400—4600 Hz、八个短窗平均；当前前端为2200—4600 Hz、257/129 tap两级抽取、完整1.024 s包络和一次4096 FFT，峰值搜索与归一化也有差异。因此约3.999倍是不同前端的宿主成本比，不是数学等价加速比。当前C9F2与独立解析包络直接DFT比较的目标频点最大幅度误差约1.05e-6；直接DFT只用于正确性验证，不在计时基线内。两套18维特征分别保存，没有宣称彼此相等。

## 文件与证据

- `run_benchmarks.py`：输入生成、工具调用、交错计时、数值验证及报告入口。
- `search_bench.c`：直接包含未改动的生产搜索代码，编译四个宏组合。
- `division_bench.c`：原生逐项除法与生产`divide_shared()`的公平算术对照。
- `envelope_bench.c`和`envelope_legacy.c`：分别包装当前和历史特征前端。
- 每个结果目录中的`raw_timings.csv`保存所有时间样本，`results.json`包含mean/p50/p95/max、计数、工具及源码哈希、数值一致性和范围说明。
- `inputs/`保存真实被计时的输入字节及场景元数据；`numeric/`保存反馈、全评分、相关、商、特征与独立DFT对照；`logs/`保存编译和运行日志，`build/`保留实际DLL及依赖文件。

正式轮生产源码/配置前后哈希相同。重新运行会生成新结果，现有统计仅适用于记录中的本机、输入和工具版本；NEON、A9双核、完整三架构及系统端到端性能均需对应硬件或RTL层另测。
