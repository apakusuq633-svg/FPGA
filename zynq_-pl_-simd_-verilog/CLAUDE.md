# 本仓库的执行约定（每次任务开始前先读）

## 0. 实测优先 —— 最重要的一条

> **所有数据都要有实测才能继续，不可以自己猜，必须得找到相应的数据才能推进。**

- **改之前先量。** 哪怕改法看起来显然。写一行精确算术模型跑一遍，
  比改 RTL 再跑 Vivado 快两个数量级。
- **给数字必须说清来源**：实测 / 解析 / 还是推的。推的要明确标出来。
- **不要用「改了一处就应该会好」结案** —— 必须复跑量到新数字。
  testbench 通过 ≠ 时序修好，这两件事没有因果关系。
- **参数扫不动就是信号**：某个参数扫一圈数字一个都不动，说明它根本没接到通路上。

**为什么**：2026-09-21 在同一个问题上连猜三次错三次（陷波深度：先怪重叠、再怪状态位宽、
实际是系数精度），每次都是**先给结论、后想去量**。代价是改了三次方向，
还把错诊断写进 README 事后订正一遍。详见 `docs/issues/004`、`docs/issues/005`。

## 1. 数据更新 —— 新数据出来立刻改旧数据

> **每一次新数据出来之后要将旧数据做修改，不能一直拖着。**

README、`docs/issues/`、脚本注释、TB 的期望值里，**凡是被新实测推翻或更新的数字，
当场改掉**。不许留「两套口径」让读者自己判断哪个是新的。

改了实现就要连带改：文档里的数字、档案里的「状态」栏、以及所有引用它的地方。
**陈旧的口径比没有口径更危险**——它看起来像结论。

### 1.1 每个实测数字都要进台账 —— `docs/measurements.md`

**规矩：量到数字，当场记进 [docs/measurements.md](docs/measurements.md)。**
验收时要能一眼看出「比原来好了多少」，所以要写全三样：

- **数值**（改前 / 改后两列都要，不能只留新数）
- **怎么量的**（命令或脚本 —— 别人要能复现）
- **口径**：实测 / 解析 / **推**。推的必须标出来，不许和实测混在一栏里报。

台账只放**数字和判据**；过程、误判、根因写进 `docs/issues/`（§2），两边互相引用。
⚠ 同一条指标有**多个口径**时（例：GSC 的 SNR 有"混响场景/无混响场景"两份），
两个数都对但**不能互相代替** —— 报数时必须写明是哪一个。

## 2. 问题档案

每解决一个问题，在 `docs/issues/` 写**单独一份**（编号不重用），并在索引里加一行。
格式固定五段：**症状 / 误判 / 根因 / 修法 / 复现指纹**。
状态分 `已修` / `待修` / `已绕过`；只跑了一半的写 `部分复核` 并说明还欠哪个量。
详见 `docs/issues/README.md`。

**修完立刻写，不要攒** —— 攒着就会忘掉「当时误判成什么」，而那恰恰是最有价值的部分。

## 3. 其它既有约定

- **回答用中文**；代码、命令、工具输出保持原样
- RTL/TB 注释**短**：一句话一个点，别写模块头长文。唯一值得留的是
  「照直觉改会坏在哪」那一句
- 改 `scripts/` 下已有脚本**原地覆盖**，不建 `v2` 变体；多脚本并存要在头部写清分工
- **整块做完再汇报**，不要中途停下来确认（TB、verify 接线、文档一起做完）。
  真正需要用户拍板的只有「改控制律 / 改架构」这类决定
- `build/` 是 **gitignored**，需要留存的文档放 `docs/`

## 4. 关键事实（容易记错的）

- 采样率 **39.0625 kHz**（40 MHz ÷ 1024），**不是 48 kHz**。见
  `rtl/array/rv32_pdm_clkgen.v` 头部
- 逐样点预算 **1024 拍**
- 两套 Vivado 配置口径不同，**时序结论不能互推**：
  - 裸 PL（`build/run_pl_bare.tcl`）**50 MHz**，台面探针
  - Zynq（`build/run_pl_flow.tcl`）**40 MHz** ← **产品配置，先跑这条**
- Vivado 在 `D:\Vivado\Vivado\2020.2\bin\vivado.bat`。**跑之前先 `Get-Process vivado`**
  —— 并发跑会坏 IP design_assist；且要用 **PowerShell** 而不是 Git Bash
  （`HOME` 会被改成 Unix 路径，BD 规则文件加载不出来）。见 `docs/issues/018`
- ⚠ **XSCT 不在 Vivado 目录下**，在 `D:\Vivado\Vitis\2020.2\bin\xsct.bat`。
  写到 `...\Vivado\2020.2\bin\xsct.bat` 会报 "not recognized as the name of a cmdlet"，
  而 PowerShell 的 `$LASTEXITCODE` 那时是**空的** ⇒ 脚本看起来"成功退出 0"，
  **实际什么都没跑**。上板脚本（`test_pdm_onboard.tcl` / `probe_pdm_firstword.tcl`）
  签名前先确认这个路径。
- 仿真一律走 **WSL**：`wsl -e bash -lc "cd /mnt/d/Users/xyfhhh/Desktop/PDM/zynq_-pl_-simd_-verilog && ..."`。
  本机没有 iverilog/vvp/yosys/gcc
  > 这条路径原来写的是 `/mnt/d/Users/xyfhhh/Desktop/pipline` —— 那是**桌面上另一个项目**
  > （有自己的 `CLAUDE.md`/`rtl`/`docs`），不是本仓库。2026-10-04 改正。
- README 是**规格**，`docs/issues/` 是**踩坑档案**，两者冲突时以档案里的实测为准并去改 README
