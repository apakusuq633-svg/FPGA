# 035 不做白化的互相关整段掉到 int16 网格以下

**状态**：已修
**日期**：2026-09-22
**阶段**：Stage 1（波束形成 DAS 基线）
**复现**：`scripts/golden/fw_srp_model.py` 的第 ②b 段

---

## 症状

DAS（延时求和波束形成）与 SRP 是**同一个扫描内核**，只差互相关序列 `R`
做不做 PHAT 白化。所以直接复用 GCC-PHAT 那条链，把白化换成 `Ψ = G >> 1`。

结果 `R` 出来是：

```
DAS: 互相关范围 [-1, 2]
```

**±2。** 累加出来的 P 范围 [4, 8]，峰值格号完全由量化噪声决定。
而白化那条同样是 ±1000 量级。

## 误判

第一反应是**符号/标度写错了** —— `>>1` 是不是该是 `>>15`，或者 G 的定标
搞反了。差点把 `gcc_finish_raw` 里的移位翻来覆去改一遍。

**不是标度错。** 那一段的算术和白化版是同一个 `G`，`X_i·conj(X_j) >> 15`
本来就是对的（白化版也用它）。**问题是量级本来就很小**。

## 根因

**链路上叠了两次 1/1024。**

1. 实数 FFT 的输出 `X` 自带 **÷1024** 的标度（每级 `>>1`，9 级，见 `fw_fft.c`）。
2. 互谱 `G = X_i·conj(X_j) >> 15` 又除了一次 2¹⁵。

于是 `G ≈ X²/2³⁵`。测试信号的 `|X|` 峰值约 6500，多数频点在 100 上下：
`G ≈ 100²/32768 ≈ 0.3` —— **一个 LSB 都不到**。取整之后整段是 0，
只有少数大频点剩下 ±1。

白化那条为什么没事：PHAT **把每个带内频点归一化到单位幅度**（Q14 的 16384），
等于把这条链的绝对标度整个丢掉了 —— 所以它从来不需要关心 G 有多小。
DAS 需要真实幅度，于是这个"看不见的 6 位余量"才第一次暴露出来。

## 修法

**块标度归一化**：扫一遍带内 `|re|+|im|` 的最大值，把整段左移到接近 Q14 满幅。

```c
for (k 带内) { a = |gr| + |gi|; if (a > mx) mx = a; }
while (mx < 8192 && sh < 14) { mx <<= 1; sh++; }
pr = gr << sh;  pi = gi << sh;
```

两点说明：

- **用 `|re|+|im|` 当上界**，移完之后每一路都 ≤ 16384，不会顶到 int16 上界
  （逆变换的反向拆分对 `|Ψ| ≤ 16384` 有依赖，见 `fw_fft.c` 的 `ifft512_real`）。
- **全局标度不影响 argmax**，所以在 DAS 里是安全的。PHAT 那条不需要这一步。

修完：互相关 **[-30, 34]**，P 范围 [46, 127] ✓。

## 复现指纹

- **白化链正常、不白化链整段是 ±1~2** ⇒ 先算一下「链路里叠了几个 1/N」，
  不要先去改移位方向。
- 一条判据：**若某个中间量的典型值 < 1 LSB，那么它之后的所有整数运算都在
  量化噪声上做**。这时候谈"算法对不对"没有意义 —— 先把标度提上来。
- 这类问题**在浮点模型里永远不会出现**（浮点没有 LSB）。所以定点模型必须
  **走整数**，不能图省事用 float 中间量 —— 用了就抓不到它。

## 留下的教训

- **白化会把标度问题藏起来**。凡是"归一化之后才用"的量，它上游的绝对标度
  从来没人验过；等到有一个不收归一化的消费者（这里是 DAS）进来，才会暴露。
  加 DAS 时顺手验一遍互相关的绝对值，比等到波形不对再回来查便宜得多。
- 同一天里第二次遇到「同一段算术，换个消费者就出问题」——
  上一次是 `docs/issues/033`（逆变换下标，形状对但每点差一点）。
  **换消费者时要把中间量本身量一遍**，这是这一轮最省时间的一条习惯。
