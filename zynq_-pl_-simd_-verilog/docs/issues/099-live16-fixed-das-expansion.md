# 099：16 麦不能只修改有效通道数量

状态：第一阶段已修，定位扩容待第二阶段。

**症状**：四麦调试建立在 8 路硬件容量上，原 DAS 的 PCM 总线、通道计数器、历史地址、延迟数组和平均除数均按 8 路编写；设置有效通道为 16 并不会形成真实 16 路通路。

**误判**：已有 16 麦 PDM 薄封装，不等于 SoC 后面的采集、DAS、PS 电平和页面也支持 16 麦。

**根因**：通道容量与有效通道数未共同参数化；手动延迟原窗口只有八项，继续扩展还会撞上有效通道数寄存器。四麦定位程序也不能用于 16 麦固定方向验收。

**修法**：SoC/顶层增加 PDM_CHANNELS 与 PDM_MICS_PER_LINE；用户选择两麦共线。DAS 总线、缓存、计数器和累加器扩展，16 路除以 16；CH8～15 延迟放到 0x3e0～0x3fc。专用 RV32 固件只读取 16 路快照统计，PS 检查有效通道数并以手动等延迟启动，GUI 显示 16 路和定位未启用。构建/实现输出独立，保留四麦实板运行状态。

**复现指纹**：`tb_das_stream` 4/8/16 路各 1200 样点通过，最长 76/76/132 拍；`tb_live16_fixed` 加载真实 RV32 固件，检查 16 路统计、1200 点 DAS/FIR 和 FIFO 丢样 0。前端共线 34 项通过。独立 Vivado 40 MHz 实现 WNS +0.044 / WHS +0.021 ns，失效端点 0；位流/XSA/ELF 配套检查 `LIVE16_FIXED_PACKAGE_PASS`。阵列尚未到位，数字与实现验收不能代替真实麦克风验收。见 [第一阶段](../live16_stage1.md)。
