# 084 线序约定有三处，却没有任何门禁守着 —— 063 那类漂移随时可以再发生

**状态**：已修
**日期**：2026-10-06
**阶段**：门禁（不是 RTL，也不上板）

---

## 症状

不是故障，是一次核查。`docs/pdm_array_spec.md` 速览表白纸黑字写着：

> **xdc 与 `board_io.md` §8 的「现状」表逐位一致**

**而没有任何东西检查过这句话。** 我逐位比了一遍，当前是对的（9/9）—— 但这句话和事实之间，只隔着"上一次手动核对"。

## 误判

这次没有"修错了地方"，但有一条**差点被漏掉**的：

我一开始把「线序约定做好了」等同于「该做的事都做完了」—— 因为 063 标着 **已修（文档）**、050 的 **19/19** 也复核过了，读起来像"这件事已经收口"。**实际上这是三件不同的事**：

| | 状态 |
|---|---|
| 文档之间的冲突（063） | ✅ 已修 |
| 换器件后封装脚是否相同（050） | ✅ 19/19 复核过 |
| **三处内容现在真的对得上吗** | ❓ **没人查过** |

`scripts/check_pins.tcl` 查的是「**两个器件的封装脚是否相同**」（050 那个用途），**不查 xdc 与文档是否一致**。

所以 **「063 已修」并不蕴含「不会再漂」** —— 修的是**内容**，没修的是**流程**。

## 根因

线序约定跨四个环节：**RTL 名 → 封装脚 → 连接器针 → 排线**。

其中最长的一段（封装脚 → 连接器针）由底板原理图决定，**Vivado 校验不到**：它只检查你写的 xdc 跟你声明的芯片型号对不对得上，不会检查 V16 在板上引到了 J3 的第几针。

于是自动校验只剩两端，中间靠人。**整个约束落在"记得改另外两处"上** —— 而那正是 063 失守的地方：引用链一路把"备选"传成了"现状"，每一步看着都合理。

## 修法

新增 `scripts/check_pdm_pins.py`，接进 `scripts/verify.ps1` **第 25 项**。

它静态核对 xdc 与 `board_io.md` §8，并顺带钉住五条**本来就写在文档里、却没人守**的不变量：

| # | 判据 | 出处 |
|---|---|---|
| 1 | xdc ↔「8 通道引脚表（现状）」**逐信号对齐**（9 个封装脚） | `pdm_array_spec.md` 速览表那句声明 |
| 2 | **PDM_CLK 在 J3.36**（25–40 段唯一紧邻地 J3.37 的信号位） | `board_io.md` §8 表下注释「**不要重排**」 |
| 3 | 8 根数据脚**都带 `PULLDOWN true`** | P-12（悬空线读成噪声 ⇒ 断线检测瞎） |
| 4 | 9 根**同一个 IOSTANDARD** | 同 bank ⇒ 同 VCCO，而 VCCO_34 从未实测 |
| 5 | 「现状表」与「J4 推荐分配表」**不许共用封装脚** | 两个连接器、同一批信号 —— **这就是 063 的形状** |
| 6 | 不许**第二个 .xdc** 也约束 PDM 脚 | 两条约束源 ⇒ 后读的赢，输的那个看着还对 |

### 反证：8/8，每一条都真的挂了

按 042 / 050 的规矩，**静态核对必须自证会失败** —— 否则就是第三个「空对空永远相等」。实测：

```
doc: V16 -> W16           FAIL  与 xdc 不符
doc: PDM_CLK 离开 J3.36    FAIL  J3 针号不变量
doc: J4 表占用 Y16         FAIL  两表共用封装脚
xdc: din3 去掉 PULLDOWN    FAIL  断线检测的前提
xdc: 空文件（0 个 PDM 脚）  FAIL  解析过短 = 不许比较（050 的形状）
doc: 截断到 120 行         FAIL  找不到表头
doc: 一行信号名被改掉       FAIL  只剩 8 条 ⇒ 不许比较
第二个 .xdc 也约束 PDM      FAIL  两条约束源
```

这 8 条**内置成 `--self-test`，而且每次跑门禁都先自动跑一遍** —— 不是只在有人记得的时候跑。理由很直接：这个仓库里"静态核对"已经空转过两次（042 判据恒真、050 拿空值比空值），而**空转的核对比没有核对更糟**，它给出一句看着像结论的 PASS。

**再验一层**：把其中一条反证改成"什么都不改"，`--self-test` 必须自己报 FAIL。实测：

```
FAIL: the negative controls did not all fire -- this check has stopped being able to fail:
      package pin disagrees with the table: ACCEPTED a mutated input
```

这一层防的是**门禁自己退化成永远通过** —— 也就是 042 / 050 的元问题。

### 顺带修掉一个自己引入的隐患

脚本第一版把**中文**（表名）打进了 PASS / FAIL 文案。而门禁里 stdout 的编码**不保证是 UTF-8** —— `UnicodeEncodeError` 会在**打印 PASS 时**把一条本来通过的检查弄成 FAIL，而且看着像"检查失败了"。

改成**输出全 ASCII**，中文只留在"匹配文档用的字符串常量"里。用 `PYTHONIOENCODING=ascii` 把正例和反例都复跑过。

## 复现 / 指纹

- **「这句一致性声明是谁在守？」** —— 文档里凡写「X 与 Y 逐位一致」的地方，先问有没有门禁。没有的话，它只是一句**冻结在写作当天**的话。
- **「某个问题标着已修，不等于它的成因被挡住了。」** —— 063 已修的是**内容**，没修的是**流程**。这两件事要分开看。
- **静态核对的脚本，解析过短必须 FAIL，不许走到比较那一步。** 042（回绕判据恒真）、050（19 个空值比空值）、084（本条），**同一个模式在这个仓库里出现了三次**。

## 还欠着的（本档案不覆盖）

这条门禁只保证**三处文字一致**。它**不能**替代上板验证：

- 排线还没做、麦还没接 ⇒ `FROZEN = 0xFF`，**9 根线一次都没在真硬件上跑通过**
- **VCCO_34 电平**从未实测（`board_io.md` 待实测）
- 载板上的 **100 kΩ 下拉（P-12）** 是否装了，未知

**指纹**：文档一致 ≠ 接线正确。这一条要等真麦接上、看 `FROZEN` 从 `0xFF` 变 `0x00` 才算闭环。
