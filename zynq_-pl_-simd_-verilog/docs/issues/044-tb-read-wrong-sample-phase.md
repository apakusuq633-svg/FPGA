# 044 TB 在 TICK=4 的 valid 上读 TICK=12 的样点 ⇒ 差一个样点

**症状** `tb_pdm_array_rx` 段 8 报 FAIL：断言「下降沿更新时两个采样相位应采到
同一个位」，实测 334912 vs 334912 —— **显示出来的两个值明明相等，却判失败**
（`$display` 是在 check 之后无条件打印的，所以看到的不是判据那一刻的值）。

**误判** 先怀疑 `SAMPLE_TICK` 参数没接进 RTL（「参数扫不动就是信号」），
又怀疑麦模型的沿检测有竞态。都不是。

**根因** 同一输出周期内，`SAMPLE_TICK=4` 的 `sample_valid` 落在第 6 拍，
`SAMPLE_TICK=12` 的落在第 14 拍。`wait_valid` 等的是**前者**，
所以那一拍读 `ch12` 拿到的是**上一个**样点。两个 DUT 各自都是对的，
错的是 TB 的读取时刻。

**修法** 加 `wait_valid12`（等 `sv12`），读 `ch12` 前先等到它自己的 valid。
两个 valid 相差 8 拍，等了之后读到的就是同一个周期号。

**顺带** 把 `check` 的 `msg` 位宽从 `8*72` 加到 `8*160`：中文按 UTF-8
一字 3 字节，72 字节装不下就截断，FAIL 信息会打成一串乱码方块 ——
**有 FAIL 却读不出是哪一条**，比没有 FAIL 更费时间。

**复现指纹** 「FAIL 但打印出来的值看着是对的」⇒ 判据和打印不在同一时刻，
先查读取时机，不要查被测逻辑。
