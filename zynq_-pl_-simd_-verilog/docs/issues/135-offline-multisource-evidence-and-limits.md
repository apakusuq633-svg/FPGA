# 135：九麦多源离线证据修复与验收边界（2026-10-27）

本轮仅离线，不连接、烧录板卡；本记录完成时未做远程 Git 操作。保留现有 PL 位流、采集参数、分类训练结果及质量门控。下述结果不是实测声场或 A9 性能。

## 原始问题与最小修改

1. sw/circular9_candidates.c candidate_support 原先要求连续 STFT 帧命中；1024点窗/512点hop 下，隔一帧的真实支持窗口仍相接，严格连续计数错误地丢弃有效证据。circular9_candidates.h c9_support_component 现在按实际窗口并集寻找连通分量，仍要求至少3次真实观测，不填补实际时间空洞；ps_circular9_aux.h 同步校验 C9B2 元数据。90%诊断覆盖率不变。
2. 低/中频的宽峰原始相干分数高、突出程度低，可能占满3个候选位置。池内排序改为 score*quality/1000，保留原始分数与门控。直接支持不足的已有次峰允许对一个已有充分支持、相隔25度以上的同频带方向做投影后的真实分帧支持检查；投影范数受原分离器限制约束，最多额外9次检查，不凭空增加峰。
3. 搜索融合15度与分离器25度契约不同，两个近候选会使整组分离拒绝。ps_circular9_tasks.h 调度时避开已经选入的25度冲突方向，仍记录 unresolved_tracks，不能把未分辨方向宣称为已诊断故障。
4. CPU1从0xFFFF8000启动，IPC段标记非缓存且使用1MB页属性。原搜索函数静态栈15960 B、prepare_bin 9568 B。将固定数组移入既有CPU1私有工作区，新增20592 B字段；搜索栈降至2432 B，分离函数（含内联）4104 B。两路分离浮点音频逐字节等同，见 scratch_equivalence.json。未测A9提速，不允许将宿主时间换算板级耗时。

## 测试与收益

- 真实 FSTF WAV 的平面波合成、实际 C 搜索/轨迹/调度/分离/特征/API 链路：基线双源0/3改为2/3；两组正常/内圈±50度交换方位均通过。强正常+弱滚动体场景仍漏检。
- 单源六类4/6，外圈和松动误分类未解决；没有针对测试场景重新训练。外圈原文件仅2秒，缺少独立留出录音。
- 19组压力：角度±15、±30、±70，故障源低6/12dB、三源及相干同录音双源存在失败；±50、等强/故障强6dB、独立时间段、两档加噪有成功样本。静音和纯噪声没有生成诊断快照。单源8ms反射两档没有生成额外可信故障。
- 现有三源数学回归、弱源/反射/突发噪声与目标保护回归、轨迹62项、支持位掩码、240次峰排列、14个物理几何方向、快照和 GUI 检查通过。具体日志保存在本目录。
- ARM最终链接通过：text500032 B、data3398 B、BSS48601168 B。未修改RTL，不声称新增Vivado实现或新WNS结果。

## 接下来为什么需要上板

先测单固定宽带声源：辅助搜索processing_us分布/最大值、skipped_hops、轨迹observations/coverage、诊断cpu1_started/completed、sequence。新增投影检查增加计算，需核对200ms辅助结果新鲜度以及150ms轨迹coast预算。CPU1诊断和辅助搜索共用缓冲，不能在没有独立工作区的情况下随意中断并重入。

再测±50度两独立声源，逐步引入6/12dB强弱差，并取得连续九路原始PCM用于离线复现。当前短快照不可当作连续诊断录音拼接。需要物理通道校准、实际声孔坐标、房间/扬声器传输及真实A9时间数据，才能判断应优先改弱源搜索、校准还是CPU预算。继续盲目提高并行搜索或调低阈值不具备证据基础。

流水线恢复、诊断可信、多电机应用验收仍是三个独立目标；本轮未完成后两项。FSTF输出仍显式未验证，不能触发可信故障方位。
