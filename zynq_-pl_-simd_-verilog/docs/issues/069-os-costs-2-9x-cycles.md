# 069 用 `-Os` 省代码，代价是 **2.9 倍拍数** —— 尺寸要在结构上解

**日期**：2026-10-04
**状态**：**已修**
**相关**：[068](068-gsc-fixed-point-three-traps.md)（同一次改动里暴露的）、
`sw/fw/fw_scene.h` / `fw_scene.c`、`scripts/build_fw.sh`、
[README §0.7](../../README.md)（PL 固件内核基线：**拍数就是产品指标**）

---

## 1. 症状

给固件加 GSC 内核之后，`build_fw.sh` 自己的越界检查报：

```
.text 0x00000000 + 0x0000212c -> 结束于 0x212c
!! .text 越过了 0x2000，会踩到数据区。
```

`.text` 上限是 **0x2000**（8 KB）：ITCM 与 DTCM 的地址空间故意重叠，
0x2000 以上的字会被加载方写进 ITCM 高半区，而数据区在 DTCM 里永远拿不到它们
（见 `link.ld` 头部）。

## 2. 误判

第一反应是"代码放不下了，那就压一压" —— 把 `-O2` 换成 **`-Os`**。
`.text` 应声降到 0x1b7c，**构建通过了**，于是看起来问题解决了。

**没有。** 它只是把问题从"尺寸"挪到了"速度"，而速度在这个工程里**更重要**：

| 做法 | `.text` | **DAS 一帧拍数** | 结果 |
|---|---|---|---|
| `static inline` + `-O2` | 0x212c | 548,305 | ✗ 越界 |
| **`-Os`** | 0x1b7c | **1,586,974**（**+2.9×**） | ⚠ 尺寸行了，**速度崩了** |
| 公共函数改 extern + `-O2` | 0x1f54 | 待量 | ✅ 选了这条 |

⚠ 而且 `-Os` 让整轮固件**撞上了 TB 的 800 万拍上限跑不完**（`retired 4,976,438` 条
指令就超时），表现为一串"指纹全是 x"的失败 —— **看着像 GSC 算错了，其实是根本没跑完**。

## 3. 根因

**代码重复，不是优化级别的问题。**

为了 DAS 和 GSC 共用，我把源信号/插值那几个函数抽进了公共头 `fw_scene.h`，
写成了 `static inline`。而 **`static inline` 在每个用到它的 .c 里各生成一份**：

- `fw_das.o` 一份
- `fw_gsc.o` 一份

`.text` 因此从 0x1b4c 涨到 0x212c（**+1,472 B**）。C 语言里"头文件放定义"
这个选择的代价，在这里就是 1.4 KB 的重复代码。

## 4. 修法

**把公共函数改成 extern：一份定义（`sw/fw/fw_scene.c`）+ 头里声明。**

```
sw/fw/fw_scene.c   定义 mix32 / scaled_src / interp_src / interp_noise
sw/fw/fw_scene.h   只留声明（fw_fd8 仍是 static inline —— 它只有 4 行，
                   且两个内核各展开一次也只几十字节）
```

结果：`-O2` 下 `.text` = **0x1f54**（余 172 B），比 `static inline` 版省 **472 B**，
且拿回了 `-O2` 的速度。

## 5. 复现 / 指纹

- **`.text` 突然涨了几百字节到几 KB，而改动只是"把函数挪进头文件"**
  ⇒ 十有八九是 `static inline`（或任何在头里的**定义**）被复制进了多个 TU。
  **判据**：`objdump -h` 看各 .o 的 `.text` 大小，同样的一段代码在几个 .o 里都出现。
- **`-Os` 让固件"跑不完"** ⇒ 先看 TB 是不是撞了拍数上限。
  本工程里 `-Os` 的代价是 **2.9×**，不是几个百分点 —— 因为内核里全是
  内层循环，`-Os` 关掉内联/展开之后每一步都变慢。
- ⚠ **不要用优化级别去解尺寸问题**。尺寸是**结构问题**（重复、死代码），
  优化级别动的是**全局的速度-尺寸权衡**，而后者的代价在这个工程里刚好最大。
- **`.text` / `.bss` / 栈三条线都已经是构建时的硬检查**（`build_fw.sh`），
  越界直接失败 —— 所以这类问题会在构建阶段暴露，不会拖到上板。
