# 049 DROP 按「整 bank」计一次 ⇒ 丢了 16 个样点只显示 1

**症状** `tb_pdm_capture` 段 5：两个 bank 都占住不还，再灌 3×CAP 个样点，
期望丢弃计数涨到 CAP（16），实测只涨到 **1**。

**误判** 第一反应是「丢弃根本没接上」—— 因为计数几乎不动，
形状和「参数扫不动」一模一样。差点去查 `write_accept` 的通路。

**根因** 不是没接上，是**单位不同**：原实现照抄了 `rv32_audio_monitor`，
在「一个 bank 采满」那一拍 `dropped_q <= dropped_q + 1`。
观测器那边**一帧就是一样点**（立体声 32 位），所以一帧记一次是对的；
而 PDM 这边**一个 bank 装 `length_q` 个样点**，同一个写法就变成"一个 bank 记一次"。
丢了 16 个样点显示 1，正好是 16 倍的关系 —— 这个整数倍就是线索。

**修法** 把计数挪到 `frame_start` 那拍，**逐样点**判 `!write_accept`：

```verilog
if (frame_start) begin
  ...
  if (!write_accept) dropped_q <= dropped_q + 1'b1;
end
```

「丢了多少个样点」才是诊断时真正要的数；「丢了几个 bank」可以由它除出来。
改完实测 0 → 16 ✓，与预期一致。

**顺带** 同一次还修了 TB 自己的两个算术错误（`FRAME_CNT` 的期望值差 100；
只灌了 2×CAP 个样点却期望有丢弃 —— 那正好把两个 bank 填满，一个都不该丢）。
**测试预期写错和 RTL 写错的现象是一样的：数字不动。**

**复现指纹** 计数类信号「动，但差一个整数倍」⇒ 先查**单位/口径**是不是照抄了
另一条通路上的语义，不要先查通路接没接上。
