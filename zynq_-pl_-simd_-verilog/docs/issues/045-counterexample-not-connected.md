# 045 反证段根本没接到被测通路上 ⇒ 参数扫一圈数字一个都不动

**症状** `tb_pdm_array_rx` 段 8（反证：把麦改成上升沿更新，两个采样相位应解出
不同结果）报 FAIL，而且**翻转 `mic_edge` 前后数字一模一样**：

```
下降沿更新：TICK=12 得 334912，TICK=4 得 334912
上升沿更新：TICK=12 得 334912，TICK=4 得 334912
```

**误判** 先按时序重新推了一遍沿检测和采样点（推了两轮），
怀疑是麦模型的 `rise` 检测有竞态、或 `bit_q` 打拍吃掉了窗口。

**根因** 两个叠在一起的问题，第二个才是致命的：

1. **段 8 把 `pat_sel[i]` 全设成了 0（LFSR）** —— 于是麦模型压根不在驱动
   任何通道。翻 `mic_edge` 改的是一个没有连到通路上的开关。
   **这正是 CLAUDE.md 说的「参数扫不动就是信号」。**
2. 就算接上了也不成立：用正弦 ΣΔ 位流做反证是**不可靠**的 —— 位流整体移位
   一位后，64 位窗口的密度几乎不变，CIC 输出变化常常为 0。反证必须用
   移位后窗口和必变的激励。

**修法** 反证改用 **LFSR**（移一位窗口和必变），并把「更新沿」提升为
**激励源本身**的属性 `src_edge`（LFSR/固定码型/麦模型统一受它控制），
而不是只挂在麦模型上。改完：

```
下降沿更新：两相位都 = 334912（一致）
上升沿更新：TICK=12 得 340288，TICK=4 得 334912，确实不同 ✓
```

**复现指纹** 反证段「翻了开关但数字不动」⇒ 先确认那个开关**连到了被测通路上**，
再讨论它的物理效应。
