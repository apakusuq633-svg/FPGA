# 092 两麦共线之后，缺一个麦**可能完全查不出来**（P-12 的前提没量过）

**状态：待修（待上板量）**。共线 RTL 已落地并通过仿真，但这一条只有实物能定。

**症状** 待验。要问的是：**共线之后拔掉某一个麦，`FROZEN` 会不会置位？**

**误判** P-12 的判据一直是这样写的：「麦不在 ⇒ 数据线悬空 ⇒ 100 kΩ 下拉把它
钉到 0 ⇒ 抽取输出恒定 ⇒ `frozen` 置位」。共线改动做完之后，我按这个判据
在 TB 第 10 段写了「缺麦 ⇒ 该通道 frozen 置位」，**它过了**。差点就此结案。

**根因** TB 里的下拉是 `tri0`，**理想瞬时的**；真实的下拉不是。

线缆电容几十 pF，下拉 100 kΩ：

```
τ = 100 kΩ × 50 pF = 5 µs
半个位周期 = 200 ns = 0.04 τ  ⇒  只掉 4%
```

⇒ 某个相位缺麦时，**那半个周期根本来不及掉到 0**，线会保持另一个麦最后驱动的
电平。相位 A 的通道于是读到**相位 B 位流的延迟副本** —— 看起来像在正常工作，
`FROZEN` **不置位**。缺一个麦完全没有症状。

而且这个错误在仿真里**永远看不见**：理想 pull 的 TB 一定过。

**修法（待上板）**
1. 用示波器（或按实际线缆电容重算）：悬空半周期在采点时刻的实际电平。
2. 三条出路选一条 —— 把下拉改小（代价是驱动电流与功耗）、换判据
   （例如判「同一条线两个通道几乎相同」，但那在声场方向正对时也会成立，
   需要再想）、或接受它并写进文档当**已知盲区**。
3. **无论选哪条，`frozen` 的语义都要在文档里改掉**：它报的是
   「这个麦的数据恒定」，**不是**「这个麦不在」。同一条还有第二个假阳性来源：
   IM73D122 的数字零是**交替码型**（datasheet §3.3 power-on behaviour），
   抽取后恒 0 ⇒ 安静环境下接满麦 `FROZEN` 照样会置位。

**⚠ 因此 `pdm_array_spec.md` 的旧验收判据「接上麦后 `FROZEN` 应变 `0x00`」是错的**，
必须换成用真实声源、且能区分「整条线两个麦都掉」与「只掉一个相位」的判据。

**复现指纹** 「器件不在 ⇒ 某个电平是确定的 ⇒ 检测得到」这类论证，**先去算那个
"确定"要多长时间建立**。RC 与位周期一比，结论常常反过来。
仿真里用理想 pull 验过的断线检测，一律标为待上板。
