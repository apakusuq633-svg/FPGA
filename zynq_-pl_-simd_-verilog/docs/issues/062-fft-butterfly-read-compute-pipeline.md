## 1. 症状：WNS 第二族在 `u_fft_bfly` 内部

`build/timing_zynq.rpt`（2026-10-03，`WNS = -0.777`）里第 4~7 条：

| # | Slack | 源 | 汇 | 级数 | 逻辑构成 |
|---|---:|---|---|---:|---|
| 4 | -0.738 | `u_fft_bfly/stage_q_reg[1]_replica_3` | `g_bank[6]/mem_reg_r2_0_63_3_5/RAMB` | 24 | CARRY4=10, **DSP48E1=2** |
| 5 | -0.722 | `u_fft_bfly/cyc_q_reg[2]` | `g_bank[2]/mem_reg_r2_0_63_15_17/RAMA` | 30 | **CARRY4=17**, DSP48E1=2 |
| 6 | -0.679 | 同上 `cyc_q` | `g_bank[3]/mem_reg_r1_0_63_12_14/RAMA` | 29 | CARRY4=16, DSP48E1=2 |
| 7 | -0.674 | 同上 `cyc_q` | `g_bank[2]/mem_reg_r1_0_63_12_14/RAMA` | 29 | CARRY4=16, DSP48E1=2 |

把第 5 条的节点按顺序摊开，形状一眼就清楚：

```
cyc_q → u_addr/wa_8[6]（地址进位链）→ wb[7] → bank 读地址
   → RAMD64E 异步读 → bq_b[4][8]
   → i___628 → CARRY4×2 → DSP48E1 → str20_i_* CARRY4 链 → bank 写口
```

即 **「地址 → 异步读 → 复数乘 → 加 → 写」全在同一拍里**，对应
`rv32_fft_bfly.v` 里那几行直白的赋值：

```verilog
tr  = (wr*br - wi*bi + 8192) >>> 14;   // 2 个 DSP48 + 一条 32 位加链
a2r = (ar + tr + 1) >>> 1;             // 再一条 32 位加链
```

**这不是疏忽，是 053 主动换来的代价。** 当初为了把「2 写口」降到「1 写口」而
选了分布式 LUTRAM，好处是**异步读**（mode4 因此能一拍一组），坏处就是异步读
把整条乘加链拉进了同一拍。BRAM 能断开（读有 1 拍延迟），但 053 里已经算过：
那样每个发生器周期都要撑成读相/写相两拍，**拍数翻倍**，更不划算。

## 2. 关键性质：这一级流水是**免费的**

要断开它，唯一办法是在「读」和「算」之间插寄存器。直觉上这会多花一拍，
但**实测枚举表明不会**：

```
每一级里，512 个元素各被碰且仅被碰一次     （重复 0）
且**相邻两组的地址交集为空**                  （9 级 × 全部相邻对，重叠 0）
```

验证方式（可直接重跑）：对每一级枚举全部 256 个蝶形的 `a`/`b`，
按 `k` 归到组，统计 ① 每个下标被读几次 ② 相邻两组的地址集合是否相交。
结果 9 级全部 `dup=0 / overlap=0`。

于是**第 n+1 组的读可以和第 n 组的写叠在同一拍** —— 写相用延迟一拍的地址，
在该拍发起下一组的读，吞吐不变。

⚠ **唯一的例外是级边界**：跨级的地址没有这个性质（第 s 级写遍全部 512 个，
第 s+1 级第一组读的那几个可能刚被写）。所以每级末尾多一个 **`flush_q` 拍，
只落盘、不读**。9 级 ⇒ **+9 拍**。

## 3. 修法

### 3.1 读相 → 算相寄存器组

```verilog
reg [31:0] qa_q [0:7], qb_q [0:7], twq [0:7];   // a 槽 / b 槽 / 旋转因子
reg        own_d [0:7];                          // mode4 的"谁是主"选择
reg [8:0]  wa_d, wb_d;   reg [2:0] half_d;       // 写相用的地址与 half
reg        phase_d, mode8_d, valid_d;
reg [2:0]  state_d;      reg [8:0] spl_d, kk_d, mm_d;
reg        same_bank_d, spl_m_wr_d;
reg        flush_q;
```

数据通路整个换成用 `qa_q/qb_q/twq`（**寄存过的那份**），控制换成 `*_d`
（**延迟一拍的那份**）。PUSH 那一条**不过流水** —— 它由核那边的 `io_fire`
组合驱动，必须当拍落盘。POP 同理保持组合（`pop_rdata` 直接吃 `bq_a`）。

### 3.2 写使能要能被"这一拍读没读"关掉

```verilog
wire rd_valid = (state_q == ST_RUN) & ~flush_q;   // 级边界的 flush 拍不算
valid_d <= rd_valid | (state_q == ST_SPLIT);      // 拆分靠既有的 ST_SPLIT_D 落盘
```

`w_m8a/w_m8b/w_m4/w_kk/w_mm` 一律再与 `valid_d` 相与。**没有这一条，
flush 拍会把污染过的操作数重算一遍写回去** —— 因为 flush 拍地址没变，
但内存已经被上一拍的写改过了。

### 3.3 一处**变简单**的地方

`xr2_q/xi2_q` 原本存在的理由是「撞 bank 留到第 1 拍时，A/B 窗已被自己的写
污染，组合值不能用」。**加了流水之后这件事不存在了** —— 算相用的都是
`qa_q/qb_q` 那份寄存值。这两个寄存器现在唯一的理由是**写口只有一个**。
`b2r_q/b2i_q` 同理（mode8 的 a' 与 b' 进同一个 bank）。

## 4. 结果

| | 修前 | 修后 |
|---|---:|---:|
| `tb_fft_addr` | 384 拍 / 2304 蝶形 | **不变** ✓ |
| `tb_fft_bfly` bin | 513/513 | **513/513 逐位一致** ✓ |
| 9 级 + 拆分拍数 | **900** | **909**（+9，与推导一致）✓ |
| 单元级总拍数 | 2950 | 2959 |

**+9 拍正好等于"9 级 × 每级 1 个 flush 拍"** —— 推导与实测吻合，
说明"相邻组地址不相交"这条性质确实被用上了（否则要 +192 拍）。

`verify.ps1` 同时 **25/25 全过**。

**⚠ flow12 那一行有个反直觉的坑，必须记下来**：加了 061 之后最终 WNS 从
-0.777 **变成 -1.224（更差）**，看着像改坏了。**不是。** 拆开看：

- **布线后**从 -1.662 **降到** -1.275 ⇒ 061 确实有效 ✓

判据是看**同一阶段的数**（布线后、布局后），不要只比最后那一行。

## 5. 复现指纹

- **源是 `u_fft_bfly/cyc_q` 或 `stage_q`，汇是 `g_bank[*]/mem_reg_*`**，
  级数 24~30，**CARRY4 占一多半且必有 `DSP48E1`** ⇒ 就是这一族。
- 若**源在核里、汇是 `g_bank[*]/RAMC`、逻辑 32 级 30.6 ns** ⇒ 那是
  **拿组合的 `push_fire` 当选址 mux 选择端**（`rv32_fft_bfly.v:213` 附近的注释），
  是另一回事，**不要"修"，要回退**。
- 改这一族时若 bin 值出现「**bin 0..256 全对、257 以后全错**」⇒ 不是本 issue，
  是拆分的 `wr_dat` 两条路取错了源（见 053 §6.2 与本文 §3.3）。
