# 046 相位斜率跨过 CIC 的零点 ⇒ 量出"色散"，其实是相位翻转

**症状** `pdm_decim.py` §7 量 CIC 群延迟，扫 0.02–0.95π 全带：

```
解析群延迟 = 94.5 个 PDM 位
相位斜率实测 = min −176.26 / max +94.50 位，全带起伏 271 位
```

**看着像严重的色散**（群延迟随频率变化 271 个位 ≈ 4.3 个输出样点）。
如果真的如此，不同频率的成分会给出不同的时间差，**定位直接糊掉** ——
这是会让人去改滤波器结构的量级。

**误判** 差点就开始考虑「要不要换成线性相位更好的滤波器」。

**根因** **CIC 在 `fs_out` 的每个倍频处幅值为 0**，相位在那里翻转 π。
`np.unwrap` 只能处理小于 π 的跳变，在真正的零点面前无能为力。
扫到 0.95π（跨了几十个零点），量出来的"色散"全是零点造成的相位假象。

**修法** 相位斜率只在**零点之间**量。把扫描范围收到 `0 – 0.8·fs_out`
（即 0–31250 Hz，第一个零点 39062.5 Hz 之下）—— 也正是我们真正用的带。
改完：

```
实测 = min 94.5000 / max 94.5000 位，全带起伏 4.37e-11 位
```

与解析值 94.5 吻合到数值精度。

**复现指纹** 群延迟/相位类测量出现**远大于预期**的起伏时，
先看扫描范围有没有跨过被测系统的零点或极点 ——
**相位在零点处必然翻转，那不是色散。**
CIC 这类带梳状零点的滤波器尤其容易踩。
