# 083　TB 的三处自欺骗：任务共用循环变量 / 访问少隔一拍 / 帧数按错状态估

写 `tb_steer` / `tb_steer_regs`（定位格号 → 8 路转向补偿）时，**三处都不是 RTL 的错**，
但症状全都长得像 RTL 坏了。三处同族：**TB 自己的时序/变量与它假定的不一样。**

## ① 任务里的等待计数用了调用方共用的变量 ⇒ for 循环只跑一轮

```verilog
integer i, g, m, k;                      // 模块级，共用
task frame;  input [IDX_W-1:0] tgt;
  begin
    wr_reg(A_TARGET, ...);
    k = 0;                                        // ← 用外面那个 k
    while (busy === 1'b1 && k < 300) begin @(posedge clk); k = k + 1; end
  end
endtask
...
for (k = 0; k < 14; k = k + 1) frame(10'd100);    // ← 只跑一轮
```

任务返回时 `k` 已经变成"等了多少拍"（~45），调用方 `k = k+1` 之后直接越过 14。
**症状**：`for` 明明写 14 帧，实际只喂了 1 帧 ⇒ FSM 锁不上 ⇒
看着像"迟滞状态机坏了"。探针打出来 `away_cnt=1` 一直不动，才反过来怀疑帧数。

**修法**：任务用自己的变量（`task frame; integer w; begin ... end endtask`）。

## ② 自增窗口**两笔之间必须多隔一拍**，否则每笔都被判 stale

壳里的 `idx_chg_q`（同步读晚一拍的保护，见 `rv32_srp_regs.v:20-26`）会把
**紧跟前一笔被接受的读**判成 stale ⇒ 返回 0 且不推进 idx。
少了那一拍间隔，现象是**每次读都返回 0** —— 而 0 是个"看着合法"的值。

**修法**：照抄已经通过的 `tb_srp_regs` 的 `core_read`：请求拍采组合值、末尾
**多一个 `@(negedge clk)`**。⚠ 这条以前就写在 `tb_srp_regs.v:16-18` 的注释里，
写新 TB 时没主动套用。

## ③ 帧数按"我以为的状态机"估，而不是按实际状态机

原来打算"喂 2 帧就锁上"，因为 `CAND_FRAMES=1`。但目标从远处来时，FSM 要走
`ACTIVE→HOLD(5 帧)→RELEASE→CANDIDATE→ACTIVE`，**约 9 帧**才切过去；
2 帧读到的其实是**上一格**的 comp —— 合法值，所以不比参照就发现不了。

**修法**：每个测试点喂够（这里取 14 帧），并**逐位对参照**；
穷举几何归 `tb_steer`（直接驱动几何核），壳体 TB 只验窗口通路 + FSM。

---

**复现/指纹** 三处的共同形状：**RTL 其实是对的，但 TB 让它看起来错了。**
遇到"明明写对了却不通过"，先问三句：
1. 这个变量是**谁**的？（任务与调用方共用的模块级变量）
2. 这两个事件之间**隔了几拍**？（脉冲宽度、同步读延迟、自增保护）
3. 我等的那个状态**实际要几拍**才到？（数一遍状态机，别估）

⚠ 与 [078](078-tb-same-timestep-combinational-read.md) / [079](079-pulse-signal-checked-as-level.md)
/ [044](044-tb-read-wrong-sample-phase.md) 同族：**判据的时刻与事件的时刻对不上**。
这三条是这个族的第四、五、六次 —— 值得单独立一条规矩：
**写 TB 时，每个 `while`/`for` 都要写清"我等的那个信号持续几拍、我在第几拍查它"。**
