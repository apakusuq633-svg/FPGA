# 052 从原理图抽 J4 线序：三个陷阱叠在一起，每一个都"看起来正常"

**背景** 换 7020 之后 J4（Bank13）可用了，但**它的逐针线序从来没有整理过** ——
`mic_array_spec.md` R-20 上一版直接写「J4 不可用」，所以没人抽过。
要按 J4 接线就得先把它抽出来。J3 那张表当年是 `board_io.md` §2 用
「按文本坐标重建」做的，那脚本在 gitignored 的 `build/` 里、早就没了，得重写。

三个坑**都不是"抽不出来"，而是"抽出来是错的但看着对"**：

## 坑 1：网络名标签画在针号**上方 2.8 个点**，不在同一水平线上

按 y 就近配对是本能反应，而它会**整体错一行**。错一行的表**每一格都有一个合法
的网络名**，看不出任何异常 —— 照着排线就是八根线全接错。

**解法（这一步是关键）**：先用 **J3 上六行已知的线序**标定偏移
（board_io.md 那张表是四来源确认过的）。实测标签在针号上方 2.8 点，
六行 **6/6 全对上**，再用同一个偏移去配 J4。
**没有"用已知的那一半去标定未知的那一半"这一步，抽出来的表不能信。**

## 坑 2：IO 站点名与封装脚在 PDF 里是**两段文本**

原理图上写的是 `IO_L20N_T3_13` 和 `Y13` 两个独立元素。

- `page.extract_text()`（不带 visitor）会把它们**粘成**
  `IO_L20N_T3_13Y13` —— 用这个写正则会以为封装脚是站点名的一部分；
- 带 visitor 的抽取**不粘**，两个分开给 —— 用那个写正则会以为封装脚不存在。

**两种抽法给出的文本不一样**，只试一种就会得出"抽不到"或"抽错了"。
两条路都跑一遍、对照着看，才知道真实结构是两段。

## 坑 3：封装脚不能按**最近邻**配

封装脚相对站点名有个固定 x 偏移（Bank13 页实测 **−4.5**），
而相邻站点的间距只有 **7.2** —— 最近邻会把每一格都挑到隔壁去。
现象是 `B13_L22_P` 和 `B13_L22_N` 都配到了同一个封装脚 `W6`。

**解法**：两组各 25 个、x 都单调 ⇒ **排序后逐一对齐**，
再用「偏移是否恒定」自检（实测全是 −4.5 ⇒ 按序配对成立）。
一个恒定偏移比一堆最近邻更能说明问题。

## 附带：两个自检写错了、报了假失败

- **J4 的重复网络名检查把 GND 也算进去** —— 而 37/39 都是 GND 是**正常的**。
  改成一揽子只查信号网络名。
- **封装脚正则会多抓 3 个**（页码、图框字母 `A4`/`B1` 之类也满足 `^[A-Z]{1,2}\d{1,2}$`），
  于是"数量对不上，不能按序配"直接把整张表拦住。加 x/y 条带约束即可。

> 这两个是**假失败**，方向与坑 1–3 相反：那三个是"错的说成对的"，
> 这两个是"对的被说成错的"。**两种都要防**：一个让错的表发出去，
> 一个让对的表用不了。

**复现指纹** 从图纸抽表格的活：**先找一组已知答案的行去标定**，
再拿标定过的规则去抽未知的部分；**只按坐标最近邻配一定会在某天错位一格**。
