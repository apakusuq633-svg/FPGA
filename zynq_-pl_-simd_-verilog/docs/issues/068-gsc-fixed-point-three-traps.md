## 0. 一句话

GSC 的**浮点**金标准早就跑通了（`check_bf.py`，混响场景 +1.25 dB）。
把它落到**定点固件**时，第一版量出来是 **−0.13 dB（比 DAS 还差）**。
三个坑填掉之后变成 **+0.25 dB**。每一个坑单独看都"像是调参问题"，**都不是**。

## 1. 症状

| 阶段 | GSC 相对 DAS |
|---|---|
| 浮点金标准（`check_bf.py`，混响，128–256 抽头） | **+1.25 dB** |
| 浮点上界（**同一场景**，L=32，μ=0.05） | **+0.56 dB** |
| **定点第一版** | **−0.13 dB** ← 比 DAS 差 |
| 定点 + 三个修正 | **+0.25 dB** |

## 2. 误判（**这份档案最值钱的部分**）

定点比浮点差 0.7 dB，我先后提了两个"最合理"的解释，**两个都被实测量翻**：

| # | 猜测 | 怎么被推翻的 |
|---|---|---|
| ① | **「32 抽头太少了」** | 把**浮点** GSC 跑在同一场景上：**L=32 拿最好值 +7.29**，L=64 → +7.23、L=128 → +7.16 —— **抽头越多反而略差**。不是抽头的问题 |
| ② | **「μ 没调好」** | `mu_num=2` 对应 μ_eff=0.0625，**就在**浮点最优 0.05 旁边。而且扫描是**单调变差**的（μ 越大越差）—— 那不是"没调好"的形状，那是"方向错了"的形状 |
| ③ | 真因 | **滤波与更新用的回归量不是同一个**（见下） |

**教训**：`①`/`②` 都是"参数类"猜测，它们的共同特征是**能靠调参掩盖**。
真正的判据是**先分清"是参数还是结构"** —— 我最后是靠「把浮点跑在同一场景上」
这一步把责任分清的：浮点正、定点负 ⇒ **是我的实现，不是场景、不是参数**。

## 3. 根因（三个，都独立）

### 3.1 滤波与更新的回归量不是同一个 ← 主因

```c
/* 错：滤波砍了 7 位，更新用完整值 */
acc += W[j][k] * (h[j][k] >> 7);        /* 滤波 */
W[j][k] += MU * e * h[j][k] / nrm;      /* 更新用 h，没砍 */
```

LMS 的梯度方向建立在 `y = ΣW·h` 上，而实际算的是 `ΣW·(h>>7)` ——
**自适应方向被系统性带偏**。这不是精度问题，是**算法不一致**。

修法：延迟线里存的就是**回归量本身**（`h = u >> Q_SHIFT`），
**滤波 / 范数 / 更新三处共用同一个值**。这是定点 NLMS 的标准做法。

### 3.2 三遍的权值轨迹不是同一条 ← 被断言抓住

SNR 必须用**同一条 W(n) 轨迹**分解（GSC 是时变的）。第一版写成：

```
pass 2 用「目标分量」滤波 → 拿本遍的 y 算误差 → 更新 W   ← 错
```

三遍滤波对象不同 ⇒ y 不同 ⇒ e 不同 ⇒ **W 轨迹各不相同**，
SNR 的分子分母来自**三个不同的滤波器**，比值没有意义。

**是这句断言抓住的**：`assert np.array_equal(W1, W2), "三遍的 W 轨迹必须逐位相同"`。

修法：**一趟同时算三条**（混合/目标/其余），**更新永远只看混合那一路**；
`e_t`/`e_o` 只用来报数。这样三条天然共用同一条轨迹，也不必存轨迹
（存要 7×16×512×4 B = 229 KB，DTCM 只有 16 KB）。

### 3.3 `e_cksum` / `p_e_target` 是**空判据** ← 最隐蔽

目标源被**精确对准** ⇒ 8 路对齐通道完全相同 ⇒ 阻塞矩阵输出 `u_j ≡ 0`
⇒ `filt(h_tgt) ≡ 0` ⇒ `e_t = d_t`，**与滤波器完全无关**。

实测证据：**L=16 与 L=32 两次跑出的 `e_cksum` 一模一样**（`0x00020B7C`）——
它不是"对上了"，是**根本没被测到**。目标那一路的滤波通路从来没被覆盖过。

**与 [042](042-cic-comb-no-wraparound.md) 同一类**：那里的判据
`(ref−got) mod 2^w == 0` 对回绕版本**恒满足**，是空判据。

修法（**尚未完成，已列为待办**）：加一个**指向误差**场景（转向偏开目标），
让目标那一路的阻塞非零。⚠ 这恰好也是 §26.6 说 GSC 会退化的条件之一，
所以这个场景本来就该有。

## 4. 修法与实测

| 项 | 值 | 怎么量的 |
|---|---|---|
| 抽头数 | **L=16** | 扫描：L=16/24/32 → 相对 DAS **+0.25/+0.18/+0.16 dB**。**抽头越少越好** —— NLMS 收敛时间 ∝ L/μ，一帧只 512 样点来不及收敛。浮点同规律 |
| μ_num | **3**（μ_eff≈0.047） | 扫描 1…16，峰在 2–3，4 起转负 |
| Q_SHIFT | **6** | 扫描 5/6/7：+6.90/+6.89/+6.88 —— **只差 0.02 dB ⇒ 0.4 dB 的差距不在回归量精度上**，别再堆 |
| 权值限幅 | ±2.0 | 实测 \|W\|max 只到 136/4096；取 ±2 同时给累加器让余量 |
| **最终** | 单麦 +0.25 / DAS +6.73 / **GSC +6.98 → 相对 DAS +0.25 dB** | `fw_gsc_model.py` + `tb_fw_gsc` |

**拿到浮点增益的比例 ≈ 45%**（0.25 / 0.56）。剩下的差距在**更新算术**里
（截断除法 + 误差通路的两次移位），**不在回归量精度** —— 见上表 Q_SHIFT 那一行。

数字全部记在 [docs/measurements.md](../measurements.md) §4/§5。

## 5. 复现 / 指纹

- **定点实现比浮点金标准差 0.5 dB 以上** ⇒ **先把浮点跑在同一个场景上**。
  浮点正、定点负 ⇒ 是实现问题，**不要去调抽头数和 μ**（我在这上面走了两条弯路）。
- **扫描结果"单调变差"**（μ 越大越差，没有峰）⇒ **不是参数问题，是结构问题**。
  正常的 NLMS 步长曲线应该是**先升后降**的。
- **`assert` 三遍的 W 轨迹逐位相等** —— 这条断言值一次完整的错误诊断。
  凡"时变系统 + 用轨迹分解 SNR"的地方都该有它。
- **判据对某个参数不敏感** ⇒ 怀疑它是空判据。
  本次的指纹：**改抽头数后 `e_cksum` 一字不变**。
  **判据必须能随被测量变化** —— 换一个会变的量（这里是 `p_e_other` / `w_ck`）。
- **7 路 × 16 抽头的 NLMS 里，"1 次除法变 112 次除法"是性能陷阱**：
  更新写成 `W[i] += num / nrm` 会让每样点做 112 次整数除法，
  而 RV32IM 的除法是多位迭代（~30 拍）。**这一条正在量**，见 measurements §3。
