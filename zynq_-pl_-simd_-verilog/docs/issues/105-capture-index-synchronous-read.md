# 105 采集INDEX之后立即读取DATA会取到上一地址

状态：已修。缓存8208字及全部1024评分逐位匹配，16麦8帧/88919音频样点、四麦17帧/34535点完整持续验收通过；固定16麦统计固件也补齐等待并通过1200点SoC。

**症状**：更新预处理后，16麦SoC仍选中格773，但空间评分与参考不一致。FFT缓存7910/8208个字不同，第0字got=0000ffe5、expected=0000ffe3。

**误判**：怀疑FFT加速器定点舍入、均值计算或注入场景错位；单纯对整帧循环移位不能完全解释差异。

**根因**：CAP INDEX寄存器与同步RAM串联，固件写地址紧接读DATA，读到上一索引。每bank样本偏移一位，bank切换首样点还来自旧索引；后续通道首样点会混入上一通道。按此模式重建输入后，实际FFT缓存与宿主结果8208字全部吻合，排除了FFT算术差异。

**修法**：四麦及16麦固件在每次CAP(7)写入之后读取一次CAP(1)，给同步数据更新留足时间，再取CAP(8)。不改变RTL时序路径；不能依赖编译器恰好在两个MMIO之间插入额外指令。

**复现/指纹**：重建固件后运行`powershell -File scripts/check_live16_xsim.ps1 -SpectraOnly`，`LIVE16_SPECTRA_PASS words=8208`。首样点/半帧边界异常且FFT表现为接近一拍相移时，应先核对INDEX到DATA的延迟，而不是放宽逐位对照。
