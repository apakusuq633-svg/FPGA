# 023 ANC 系数运算没流水 ⇒ 40 MHz 时序挂掉

**症状** 产品配置（Zynq，FCLK 40 MHz）**WNS = −5.799 ns，186 个端点失效**。
对比之前记录的 **+2.238 ns**，**回退了 8 ns**。

**误判** 一开始以为"回归在核里"——因为裸 PL 50 MHz 那条的关键路径显示在
`u_ex_mem_reg` 的 payload 触发器上（`+0.024 → −1.436`），而我改过 vec 单元的 `ch` 位宽。

**根因** 报告里 `u_anc` 出现 **76 次**，最差路径就是它：

```
Source:      u_anc/nk_rho_q_reg[1][1]/C
Destination: u_anc/st_y1_reg[1][15]/D
Data Path Delay: 30.359ns  (logic 19.973 + route 10.386)
```

`ρ 寄存器 → 系数运算 → 双二阶 MAC` 一条路上串了 **3 级乘法**全组合：

1. `r_mul = (32768−ρ) × 深度`
2. `rc_mul = r × cosω`、`rr_mul = r × r`
3. `term = 系数 × 状态`（MAC）

25 ns 装不下。这是我改成零点半径式（见 004）时引进的。

**状态** ✅ **已修（实测判定）**：40 MHz WNS **−5.799 → −0.413 ns**，失效端点 **186 → 25**，
TNS **−732.390 → −4.603**；`u_anc` 在报告里从 **76 次降到 13 次**，**已不在关键路径上**。
功能未受影响（`tb_anc_hybrid` PASS 1536 帧逐位相等；`tb_anc_notch` 频响逐位不变：
60 Hz −20.176 / 150 Hz −2.594 / 10 Hz −5.137 dB）。代价实测：序列每帧 +8 拍（总周期 +120088）。

> **026 追记**：陷波链已整个撤掉，本文里那些系数相位（`bp_*`/`nkc_*`）随之不复存在，
> 帧序列从 68 拍缩到 **50 拍**。**上面的 WNS 数字是 68 拍版本的实测，不能套到新序列上** ——
> 新序列的时序**没有复测**（时序单独量），面积/时序影响见 026 的"未实测"一节。

> 那个版本里还有 ANC 陷波链（026 已整个撤掉）。**当前全设计时序已闭合**：
> `WNS = +0.726 ns`、失败端点 **0** —— 靠

**仍未收敛**：还差 0.413 ns、25 个端点。新的最差路径是 `u_regs/halt_q` → 核
`u_ex_mem_reg` payload。**这条路径是否由我引入，未归因** —— 上一次 Zynq 的报告被这趟覆盖了，
裸 PL 那份没有 PS（`halt_q` 不在顶层里），两个都不能当基线。
**要归因必须把 RTL 回退后重跑一次做对照**，我没有那个数据，所以不下结论。

**一条推断（不是实测）**：两条失效路径的**目的地都在** `u_ex_mem_reg` payload 的 D 上
（裸 PL 那条 Source 和 Destination 都在它上面，28 级 / 走线占 49%）。
**payload 的 D 锥本身是瓶颈**，谁的驱动最慢谁就冒出来 —— 但这只是形状相似，没量过。

**修法** 加一个 **8 拍的系数预算相位**（步 0..7，每节 2 拍），把两级乘法拆开锁存：

- 第 1 拍：算 `r` 并锁存 → 系数寄存器的 D 锥里只有 1 级乘法
- 第 2 拍：用**锁存好**的 `r` 算 5 个系数 → 同样只有 1 级
- MAC 那一拍只读寄存器 → 链上只剩 1 级乘法

用**上一帧**的 `bp_cos_q`（cosω 只在频率变时才变，差一帧无害）。

**踩到的两个附带坑**（都记下来，都很快）：
1. `S_END` 从 60 变成 68，但 `step_q` 只有 **6 位（最大 63）** —— 序列永远到不了收尾、
   `busy_q` 不清，`tb_anc_nco` 直接超时。**加长序列时必须先数计数器的位宽。**
2. 系数预算用上一帧的 `bp_cos_q`，而它在第一帧还是 **X** —— X 会经系数 → 双二阶 →
   `NOUT` 一路污染到固件。复位里给了初值 `16384`（cos0=1），配上 depth=0 正好是旁路。
   **凡是"跨帧沿用上一帧的值"，第一帧的初值必须显式给。**

**复现/指纹** 关键路径的 Source/Destination **都在同一个子模块内部**，
而且是"配置寄存器 → 状态寄存器"——这类形状就是"参数运算没流水"，
不是逻辑功能错。凡是"配置量参与实时运算"的地方都要预算或流水。

## 附：这次改动引入的一处**模型与 RTL 的行为差异**（已实测确认存在，影响未评估）

系数预算相位用的是**上一帧**的 `bp_cos_q`，所以陷波系数比模型**晚一帧**。
`FwModel`/`NotchBank` 用的是**当帧**的 cosω。

- 频率**静态**时两者一致（`bp_cos_q` 只在频率变时才变），所以
  `tb_anc_hybrid` 里把频率一次性配好之后，这个差异**看不出来**。
- 频率**运行期变化**时（§7 Stage 4 变转速、或 PS 检测到新音调后下发）
  两者会不一致，**差一帧**。这一条**还没量过影响**，不要当成"无害"。
