# PS DAS 软件通路与运行方法

2026-10-12 GUI 电平/包络修正及四麦上板结果见 [信号验证进度](gui_signal_validation.md)。真实通路已上板运行；下文历史回放阶段的“尚未上板”不代表当前状态。

2026-10-12 更新：真实模式已对齐 PL 的 0x380 FIFO，启动流程及运行边界见 [FIFO 对接说明](ps_fifo_integration.md)。以下双 bank 描述属于原约定接口及回放基线。

2026-10-11。当前完成不依赖 PL 新接口和真实信号的 PS 软件通路，尚未上板证明实时性能或诊断准确率。

CPU0 接收 512 点 int16 音频块，检查格式、序号和连续性，拼成 40000 点诊断段；CPU1 复制完整段到缓存区后归还槽，执行特征、分类和图谱计算。CPU0 同时维护网络服务。共享队列独占一个 1 MB 非缓存 DDR 区域，槽状态采用 acquire/release 原子操作；结果经 OCM 序列锁传递。

断流、转向、目标或来源变化会清除未完成段；队列满时统计丢样，不覆盖完成段。诊断位置来自音频段元数据，避免旧诊断绑定新定位。网页显示首样点、转向版本、来源、计算耗时、丢样计数和同段音频频谱、包络谱。图谱按自身峰值归一化，并非校准声压；没有单麦对照或完整 SRP 热力图。

默认回放将合成信号转换成 int16 音频块，走完整接收、拼段和诊断通路，不访问新增 PL 窗口。回放目标是固定合成元数据，不代表真实定位或 DAS 增强。采样率契约 39062.5 Hz，40000 点对应 1.024 秒，转频默认 25 Hz；实际速率需上板测量。

## 运行

在仓库根目录执行：

```powershell
python scripts/check_ps_apps.py
node scripts/check_ui_page.js
powershell -File scripts/build_ui_pipeline.ps1
```

输出 `build/ui_pipeline_replay/ui.elf`。构建脚本不烧写或修改外部 Vitis 工作区；默认使用 E 盘 Cortex-A9 工具链和 D 盘已有 BSP，可用参数调整路径。`build/gui_preview.html` 使用宿主完整通路测试产生的 JSON，可直接打开；其中耗时不是板上实测值。

实现约定音频窗口的位流到位后构建真实模式：

```powershell
powershell -File scripts/build_ui_pipeline.ps1 -Live -MatchingPlWindow
```

输出 `build/ui_pipeline_live/ui.elf`。该开关是匹配位流的显式构建条件，不能证明硬件已实现。接口错误会报告并停止接收，不自动切换回放。旧位流未译码的 AXI 访问可能触发 ARM 异常，不能靠读 MAGIC 试探。

## 验证边界

宿主执行测试覆盖双 bank 协议、PCM 端序、拼段余量、序号回绕、异常和满队列；线程压力测试检查并发数据完整性；完整通路测试执行特征、分类、图谱、IPC 和 JSON，并比较 PCM 量化前后票数。回放与真实模式均完成 Cortex-A9 编译及现有 BSP 链接，队列地址和大小满足 1 MB 对齐。CPU1 主函数静态栈用量 2552 字节，调用链与运行余量仍需板上确认。

剩余依赖硬件或真实数据：PL 双 bank 和 AXI 窗口；双核缓存属性、网络、异常恢复的上板验收；实测诊断耗时与连续运行丢样；真实转速、轴承参数和模型适配。合成回放通过不等于真实故障识别有效。
